# AI Bookkeeping — 栗子记账任务系统

## 产品体验

这是一款鼓励每天记账的私人财务系统。核心循环是：完成今日记账任务、处理异常、获得成长反馈，同时仍能快速看清资金流向、账户余额和资产价值。

## 视觉签名

- 首页是“财务信号舞台”：超大中文动词、轨道化进度、斜切构图和荧光任务信号共同表达记录行为。
- Arc Browser 式悬浮工作区被重新解释为编辑式异形面板，不使用整齐同质的 SaaS 圆角卡片阵列。
- 像素狐狸“栗子”只出现在任务、阶段、徽章和庆祝场景，不干扰严肃财务信息。
- 首页可以大胆、高对比；交易、账户和设置页必须降低视觉噪声，保持高频操作效率。

## 色彩令牌

| 状态 | 色值 | 用途 |
|---|---|---|
| 未完成 | `#DDE5F4` | 未记账、待办、低优先级背景 |
| 主行动 | `#6257F6` | 导航选中、主要按钮、焦点 |
| 任务信号 | `#D8FF45` | 今日任务、主行动、状态轨道 |
| 今日完成 | `#FF9A5A` | 栗子成长、完成反馈、连续记账 |
| 成功 | `#2CB99A` | 已处理、余额确认 |
| 异常 | `#EE7180` | 异常提醒、危险状态 |
| 正文 | `#20253F` | 标题与主要数字 |
| 次要文字 | `#69708A` | 说明和元数据 |

里程碑庆祝可短时使用彩虹渐变；普通财务页面不得把彩虹作为常驻装饰。

## 字体

- 正文、表格、表单和设置项使用微软雅黑、苹方等系统现代无衬线中文字体，优先保证长时间阅读。
- Windows 中文环境必须把 `Microsoft YaHei UI`、`Microsoft YaHei` 放在 Inter 等西文字体之前，并禁用浏览器伪造字重；正文不小于 14px，辅助文字不小于 13px。
- 首页主标题与少量一级栏目标题使用本地打包的“站酷庆科黄油体”，不用于正文或密集数据。
- 金额、进度、账户编号与英文状态标签使用本地打包的 JetBrains Mono Variable，并启用等宽数字。
- 两款附加字体均采用 SIL Open Font License；字体资源随应用打包，NAS 离线部署不得依赖外部字体服务。

### 浏览器可读性验收

- 截图只能作为视觉记录，不能代替真实浏览器验收；每次改动必须在 Windows Chrome 的 100% 与 125% 缩放下检查正文、卡片标题、状态文字和表单。
- 不得同时强制显示同一输入框的浮动标签与 placeholder；未聚焦输入框的 placeholder 应隐藏，聚焦后再显示。
- 避免对正文所在容器使用小数像素位移、缩放或持续 transform；半透明与模糊只用于独立背景层，不作用于文字层。
- 弹窗编辑层必须高于抽屉与遮罩：普通抽屉使用 3000 层级，编辑弹窗使用 4500 层级；打开编辑弹窗前先卸载详情抽屉。
- 最终验收读取浏览器计算样式并实际点击交互，不能因自动截图看起来清楚就判定通过。

## 布局

- 1280px 以上：完整悬浮侧栏和顶部 HUD；内容卡片响应式铺开。
- 1024–1279px：侧栏可折叠，保留顶部任务状态和快速记账。
- 交易页采用筛选栏、列表和可扩展详情结构；账户页优先卡片化展示；设置页限制内容宽度。
- 主要面板使用交替切角 `3px 24px 3px 24px`，配合硬质错位阴影；表格内部保持克制、易扫读。

## 钱包卡片

- 钱包使用“账户印章”系统，不能只用不同渐变色区分类别。
- 微信、支付宝、花呗、京东白条、现金、储蓄、信用和投资账户具有独立的大字徽记、几何纹样与英文副标。
- 卡片根据账户名称和类别自动选择视觉身份；未知数字账户使用通用数字价值图腾。
- 艺术图案属于背景层，账户名称、余额、余额性质和末四位始终位于最高信息层。
- 卡片可叠放并在悬浮时展开，但不得依赖悬浮才能读取余额。

## 账户展厅

- 账户页采用“侧边栏叙事 + 3D 账户轨道 + 选中详情”的展厅结构，不再以纵向表格作为主视觉。
- 侧边栏用一句与资金角色相关的短叙事建立页面语境；文案保持克制，不遮挡账户分类和资产汇总。
- 当前分类的账户以三维卡片轮播展示；中央卡片为当前选择，相邻卡片保留可辨识的身份图案、名称与余额。
- 点击任意可见卡片立即将其移至中央，并在右侧更新账户余额、账户角色、币种、隐藏状态和备注，不额外跳转页面。
- 详情面板保留“查看流水”和“编辑账户”两个明确出口；切换账户只改变本地选中态，不触发额外 AI 或数据请求。
- 卡片轮播必须支持前后按钮、键盘焦点和循环切换；在减少动态效果模式下取消景深过渡，但保持层级与内容完整。
- 窄屏时详情面板移动到轮播下方，账户卡片仍需保证名称、余额和身份标记可读。

## 交易日历

- 从桌面侧栏进入“交易详情”时，默认展示完整月历，而不是先展示流水表格。
- 月历初始占满工作区；用户实际点击日期后，月历收窄到左侧，右侧显示当天交易。
- 日期详情按时间、分类、描述、账户和金额组织；点击交易继续进入原有编辑流程。
- 右侧没有交易时必须给出补记入口；“展开日历”可退出分栏，不清除当前日期。
- 切换日期只筛选已经加载的当月数据，不为每次点击重复调用接口。

## 动效

- 页面切换：`420–520ms cubic-bezier(0.22, 1, 0.36, 1)`，只使用透明度与轻位移。
- 直接交互：`180–240ms`，按钮按压、卡片轻抬和任务完成反馈。
- 异常出现时可播放一次短暂珊瑚色波纹；普通背景不持续漂移。
- 3/7/14/30/100/365 天里程碑允许最多 3 秒全屏庆祝。
- 尊重“减少动态效果”系统设置，并提供应用内动效开关。

## 游戏化规则

- 今日任务：至少记录一笔；处理全部异常。无交易日可点击“今日无账”。
- 今日任务未完成时使用完整引导舞台；完成后由全局顶部导航接管任务 Dock，伙伴、真实完成状态、进度、快速记账与系统操作必须融合在同一玻璃层中，首页不再渲染第二条完成卡片。
- 已完成的今日任务从待办区移除，全部完成后待办区消失；全局 Dock 始终吸附在视口顶部，必须使用可透出并高斯模糊下层内容的单一玻璃材质，内部状态只用细分隔线，不再嵌套玻璃卡片。
- 首笔或“今日无账”奖励 50 XP，后续每笔 5 XP，每日最多 100 XP。
- 导入账单逐条计入经验，但同样受每日上限约束。
- 成长阶段：幼狐、探索者、记账达人、财富守护者；经验永不衰减。
- 所有进度、连续天数和徽章必须来自真实记录，禁止展示伪造的成长数据。

## 可访问性与安全

- 正文对比度达到 WCAG AA；图标按钮必须有可访问名称或提示。
- 焦点环始终可见，信息不能只靠颜色表达。
- 删除、恢复、覆盖等高风险操作使用珊瑚红警示和二次确认，栗子可出现但不能弱化风险。
- 首版仅简体中文；深色模式入口保持禁用并显示“即将开放”。
