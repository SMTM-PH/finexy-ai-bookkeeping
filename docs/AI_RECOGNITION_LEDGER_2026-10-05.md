# AI 识别的账本上下文

日期：2026-10-05。文字、图片及 MCP 图片识别已接通服务端账本范围，补充 [AI 队列服务端合同](AI_REVIEW_LEDGER_BACKEND_2026-10-05.md)。本专项只返回识别草稿，不新增流水、不改变余额、不自动创建待复核记录。Web/Android 生产页面的账本选择、持久队列及原子确认尚未接入，现有客户端仍维持默认个人账本范围；正式服务与主应用未升级。

## 范围与匹配

旧识别代码按当前账号读取所有账本账户，并以名称覆盖同名匹配。本轮确认的是源码行为，没有据此认定真实账本发生过误写。

新上下文在账本所有者数据分片读取资源，先检查直接账本成员权限，在读取事务中再次检查；模型调用结束后重新检查当前权限。调用模型期间不持有数据库事务。识别过程中被移除的成员不能取得返回草稿；使用量仍归已经实际发出请求的人。

- 账户只来自选定账本，排除删除、隐藏及多账户父项；子账户要求父项同账本、可见且结构有效。
- 分类来自账本所有者，要求叶子、类型有效、父级存在且可见；不改用成员个人分类。
- 标签仍是私人资源。只有账本所有者自己的识别会使用其标签；管理员、普通成员和只读成员均不会向模型发送所有者私有标签，也不会返回对应标签 ID。
- 同名账户、同类型同名分类及同名标签不自动选择其中一个，也不作为确定资源名发送。模型即使返回该名称，ID 仍留空，交给用户明确匹配；不同分类类型的同名项分别处理。
- 名称按稳定顺序发送。退款保留负数；金额继续使用整数最小货币单位，转账保留来源和目标金额。识别草稿不是写入授权，确认时仍须复核完整资源与账本合同。

只读成员可以识别自己提交的内容并读取允许的账本资源；这不会授予创建队列或确认记账权限。实际计量使用请求人的 UID，不伪装为账本所有者。读取时的资源快照可能在模型调用期间改变，后续创建/确认必须按 ID 重新校验，不凭识别结果跳过校验。

## 接口兼容

| 入口 | 账本合同 |
| --- | --- |
| `POST api/v1/llm/transactions/recognize_text.json` | JSON 的 `ledgerId` 为十进制 ID 字符串，非负；省略保留默认个人账本 `0` |
| `POST api/v1/llm/transactions/recognize_receipt_image.json` | multipart 中至多一个 `ledgerId`，必须为规范非负十进制字符串；省略为 `0`。若同时提供 query `ledgerId`，必须与 multipart 选择一致，query 不代替表单选择 |
| MCP `recognize_receipt_image` | 使用正常生成令牌中绑定的 `AgentLedgerId`，不接受调用者更换账本；返回 `ledger_id` 字符串。只读 scope 仍可获得草稿，负数退款金额保留 |

非默认账本的 HTTP 草稿响应包含 `ledgerId` 字符串。默认账本 `0` 继续省略此字段，避免改变旧持久创建请求的 JSON 内容及回执 hash；新客户端应从打开时选择的账本持久保存来源。创建队列时，识别数据中的非零账本必须与外层队列账本相同，负账本拒绝；旧省略/零字段保留兼容。

共享 MCP 令牌受实时成员检查约束；成员移除后，旧令牌的工具请求在调用模型之前即被拒绝。增加账本响应字段没有升级旧令牌权限。

文字识别与图片识别复用同一结果解析器，移除了文字路径中记录原始模型响应、时间、金额和无效类型的日志。模型请求及 JSON 失败日志保留请求人及失败类别，不输出提供方错误正文。提示词模板缓存加读写锁，避免首次并发识别时写全局 map 竞争。
