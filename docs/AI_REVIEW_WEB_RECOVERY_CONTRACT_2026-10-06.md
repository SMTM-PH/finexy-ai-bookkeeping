## 生产模块

- `src/models/ai_review_ledger.ts`：账本队列、能力、创建、原子确认、回执与持久记录类型；ID、金额、状态、资源方向、完整回包及原账本校验。
- `src/stores/aiReviewLedger.ts`：当前账本完整分页、详情、识别、创建与确认日志、原请求重试、回执处理、忽略/恢复/删除。
- `src/lib/userstate.ts`：创建与确认分别按服务器路径、用户、账本保存；沿用应用锁加密及真实 IndexedDB 跨标签页串行锁，登录退出后保留未确认结果。
- `src/lib/services.ts`：明确账本、账号保护和原子 API 请求；识别 JSON/multipart 均携带原账本。接口错误转换为可见说明，不将 Axios 配置、令牌或财务内容传给调用者的通用日志。

服务端能力响应新增 `recognitionLedgerContext: true`，不改变合同版本或成员权限。新识别 store 要求此能力，避免将只有队列合同的较旧服务误当作支持共享识别。新创建/确认要求原子确认、内容绑定、删除回执、游标分页等完整能力；缺失时提示升级并保留本机内容，不回退到旧流水新增及 `resolve` 的两次写入。

## 恢复与展示合同

用户明确调用创建/确认后，先保存完整 JSON 快照和稳定键，再发送写入。存储失败阻止 HTTP。每个账本分别至多保留一笔待核对创建与一笔待核对确认；结果未知时禁止另一个请求替代原日志，也不能忽略、恢复或删除正在确认的原条目。重试使用保存的全部字段，包括时间、时区、双金额、隐藏金额、标签、附件、位置和备注。

回包必须匹配原账本、队列 ID 和字符串流水 ID；创建回包还核对原来源及识别内容。默认识别省略账本的旧数据沿用队列自身归属，不据此改变来源账本。原文本的规范化严格匹配服务端 Unicode White_Space，保留原快照，避免 JavaScript `trim()` 对 U+0085/BOM 的差异使合法回执无法核对。

明确回执先可靠落盘。此后重试仅返回该回执，不再发送财务写入；页面应重新读取原对象并明确处理回执。读取失败保留回执，不生成替代入账。删除回执不能触发替代创建。账号变化阻止旧回包落到新身份；账本切换时允许将已经收到的回执保存回原账本，但不填入新账本展示。

队列读取先核验实时成员和服务能力，以 `beforeId` 游标完整读取，再公布快照。所有 ID 保持十进制字符串，以 BigInt 比较顺序；分页重复、乱序、跨账本、错误状态、删除行、缺少 `result` 或后续页失败均拒绝。失败不表示真实空队列，不发布第一页作为完整结果。切换立即清空展示，迟到或被后续加载替代的请求标为过期。

只读成员可以读队列和识别；确认/创建另核验写权限。新确认先读取对象 `editable` 和状态，普通成员不能处理他人来源；管理员/所有者权限仍由服务端对象校验执行。未知请求重试时重新核验权限，撤权保留原日志。已知回执仅供原账号在本机核对，不授予服务端权限。

本轮还修正了共用存储读取：空字符串、JSON null、数组和标量不再被当作“没有记录”，损坏记录阻止替代请求。应用锁变更会同步重加密两类 AI 日志，锁定时不能读取或改写；不会为了恢复而清空原数据。

9 组浏览器专项：

1. 创建实际提交后丢回包，重载恢复原来源、快照和稳定键，返回原队列 ID。
2. 原子确认实际提交后丢回包，重载及两个真实 IndexedDB 标签页重试返回同一流水；负支出只冲减一次。
3. 已知回执后详情读取失败不再发送确认，明确处理回执后另一页读取不到该日志。
4. 实际新增 101 条队列，完整游标分页；缺少 `result` 显示失败，不形成有效空快照。
5. 持有实际队列响应时切换账本，旧回包不能填入新账本。
6. 只读成员只读、普通成员不能确认他人来源，确认丢回包后移除成员，原请求保留且重试被拒绝。
7. 旧服务 404 阻止写入并保留创建；忽略条目可经真实接口明确恢复。
8. 同时持有两页原条目读取，再用不同键竞争确认，实际 IndexedDB 锁只允许一个财务 HTTP，两页保留同一个获胜快照。
9. 真实 localStorage 中的损坏 payload 在发送确认前失败关闭。

首轮原请求提示与分页夹具的失败日志、首轮类型检查失败日志保留，以最终修正后的门禁为准。后续审查补充了损坏可选回执、Unicode 规范化与迟到错误标记，重新运行完整 Web 门禁及 9 组浏览器验收。
