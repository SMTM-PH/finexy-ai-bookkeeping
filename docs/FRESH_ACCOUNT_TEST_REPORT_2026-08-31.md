## 新发现的问题

### FRESH-01【低】创建账户的初始余额在近期活动中显示为支出

**复现步骤**

1. 注册新账号。
2. 在总览页创建账户“微信零钱”，初始余额填写 ¥150。
3. 查看总览页“近期活动”或全部流水。

**实际结果**

- 账户余额正确显示为 ¥150。
- 但近期活动新增一条“支出 -¥150”，分类为“未分类”。
- 全部流水中该记录类型也显示为“支出”。
- 支出统计仍为 ¥0，说明内部余额计算没有被错误扣减。

**预期结果**

初始余额应显示为“期初余额 / 余额调整 / 开户余额”等独立类型，不应伪装成真实支出。

**影响**

用户查看流水时会误以为发生了一笔 ¥150 消费；导出、对账或按流水理解资金来源时容易产生误判。当前未发现统计金额被污染。

**建议**

为初始余额使用专用展示类型和文案，并在流水列表、详情、导出中保持一致。

### FRESH-02【低】交易描述在流水列表中重复显示

**复现步骤**

1. 在总览页新增一笔交易。
2. 描述填写“全新账号收入测试”。
3. 打开全部流水。

**实际结果**

交易列的 DOM 同时渲染：

```html
<b>全新账号收入测试</b>
<small>全新账号收入测试</small>
```

页面上表现为同一描述连续显示两次。

**预期结果**

描述只显示一次；如果需要标题和备注两行，应提供独立字段或仅在备注非空时显示副标题。

**影响**

流水列表信息冗余，较长描述会挤压类型、分类和金额列的可读空间。

## 已验证的既有问题

- 支出金额契约：本版本 UI 新增 ¥5 后页面显示 `-¥5.00`，接口记录 `type=3`、`sourceAmount=500`；普通支出金额按当前后端契约以正数存储，余额扣减和支出汇总均正确。
- 分类过滤：切换支出/收入时选择器分别显示对应类型分类，没有混入另一类型分类。
- 中文预设标签：网页注册的 `zh-Hans` 账号生成中文标签；此前修复也覆盖 API 注册的 `zh-CN`、`zh-SG` 等 locale。
- 统计刷新：新增、删除交易后总览统计自动更新，无需点击刷新按钮。
- 深链路由：分类和标签 URL 直接访问均恢复到正确页面。
- 移动端扩展名入口：`/mobile.html` 返回移动端 HTML，状态码 200。

## 结论

本轮全新账号主流程未发现阻断性或中高严重度功能故障。建议优先修复 FRESH-01 的流水语义问题，再处理 FRESH-02 的重复展示问题。
