## 3. 第一批：AI 跨端闭环

### F01：完成正在开发的移动 Web 队列与确认

现有接入位于 [队列页](../src/views/mobile/ai/ReviewPage.vue)、[移动编辑器](../src/views/mobile/transactions/EditPage.vue)、[公共确认面板](../src/components/common/AIReviewConfirmationPanel.vue) 和 [恢复 store](../src/stores/aiReviewLedger.ts)。后续在这些实现上收尾，普通记账和模板创建保持各自合同。

进行中记录位于本机 `artifacts/ai-review-mobile-20261006/`，目录日期沿用开工日期；部分用例通过后的失败日志须保留，不替换为整套通过结论。

- 先定位“明确丢弃草稿 → 返回队列”验证未通过的原因，区分产品行为与脚本没有等待异步保存/删除完成的时序问题；出口是确认删除已提交、离开不重建草稿、队列恢复提示同步消失。**（2026-10-07 已定位为脚本时序：丢弃经 IndexedDB 串行事务提交，脚本在提交前跳转；已在专项脚本中等待生产面板与账本范围本机键的提交信号，见 [移动 Web 队列](AI_REVIEW_MOBILE_QUEUE_2026-10-07.md)。）**
- 将待复核、已忽略、原条目恢复、读取失败和真实空态完整验收；换账本或账号立即清除旧展示，迟到响应不能覆盖新上下文。
- 保留未完成计算式、日期、时区、双金额和完整字段；未匹配账户/分类不默认填入首项。已知回执只读取，未知结果只重试原键与原快照。
- 补默认个人账本 `0`、共享四角色、降权、退款、内部/外部转账、跨币种、存储失败、双标签页及整个浏览器进程重启。
- 在同一候选上完成移动专项、桌面确认与来源关联回归、普通移动记账/模板回归；涉及 Agent 公共入口时补 Agent 门禁。

**完成标准：**专项完整通过并生成最终结果；候选与源码/静态资源一致；未运行项单列。单个场景通过或某次截图不能代替该出口。

### F02：接通移动 Web 来源录入

复用 [桌面来源合同](AI_REVIEW_SOURCE_2026-10-06.md) 的状态层和图片处理，按移动页面适配，避免复制两套恢复逻辑。

- 当前账本文字、手动粘贴和图片入口统一进入来源流程；剪贴板读取失败允许手动输入，不能自动发送给模型。
- 图片支持四角裁剪、旋转、真实预览与可访问的替代操作；发送前明确说明来源、服务模型和账本上下文。
- 来源、识别结果和队列创建请求持久保存；识别失败可重试或手动复核。创建待复核条目与确认财务入账是两次明确操作。
- 旧移动识别入口逐一迁入新流程，避免把完整财务字段塞入 URL 后走普通新增接口；新服务能力缺失时保留草稿并明确提示。

**完成标准：**真实文字/图片请求验证账本上下文；来源恢复、取消、存储失败、丢回包、账号/账本切换通过；关联桌面来源专项仍通过。

### F03 / F04：Android 持久层与生产页面

在 [Android data 层](../android/app/src/main/java/com/finexy/mobile/data/) 和 [现有 AI 页面](../android/app/src/main/java/com/finexy/mobile/AIReviewScreens.kt) 接续。先实现可靠状态，再开放完整界面。

- 沿用服务器/用户/账本隔离、稳定本地 ID、Repository Flow 和 WorkManager；服务端复核条目实际所属账本与实时权限。
- 如需更改 Room，新增 migration，并同步备份 schema 与新旧兼容测试；不能使用 destructive migration。
- 草稿、不可变确认请求和明确回执分别保存；Worker 恢复不能构造替代新增，已知回执后的失败仅重新读取。
- 使用当前账本真实账户/分类和原币金额；来源发送、复核、预览、确认、忽略/恢复均有可见状态和错误。
- 独立 QA 包或专用测试环境验证活动重建、丢回包、降权、A/B/默认隔离及新 PID Worker；不卸载、不清除主应用数据。

**完成标准：**数据/迁移/备份、隔离 API、生产页面和 prepare → 终止进程 → 新 PID Worker → verify 均有独立证据；跳过的 Docker 用例不算通过。

### F05：当前账本提示与恢复入口

首页和通知显示当前账本的 AI 待复核、周期待确认与同步失败。不同来源分别保留状态，计数失败显示失败/重试，不能成为零。点击进入原账本和原条目；条目移出队列后，本机未核对回执仍有恢复入口。通知到达不直接改变余额。

**完成标准：**账本切换、无权限、迟到响应、零条/失败、隐藏金额以及确认后的刷新均通过；没有可用计数时不显示占位数字。

## 4. 第二批：统一报告、导出与月度首页

### F06：先建立统一查询和服务端出口

详细合同沿用 [报告范围审计](REPORT_SCOPE_AUDIT_2026-10-04.md)。日期、类型、账户、分类、标签五个维度使用同一规范化查询；账本、币种及展示时区是明确上下文。

- 日期按自然日转换为 `[start, endExclusive)`，覆盖跨年、月末和 DST；API 秒与 Room 毫秒在边界转换。
- 账户/分类/标签按 ID 和实际归属处理，同名资源不合并；共享标签读取不扩大管理权限。
- 收入、支出、退款按原币整数汇总；转账按一笔逻辑流水去重并保留双侧，余额调整不混入收支；超限、缺元数据或部分分页不能生成完整报告。
- 图表、合计、流水、下钻和导出读取同一集合。报表 CSV 与现有账号备份导出保持各自用途和兼容性。
- 导出预览绑定查询和数据基线；身份、账本、过滤或基线变化后重新核对。处理公式开头文本、逗号、引号和换行转义。

**完成标准：**CGO=1 专项和隔离 HTTP 验证四角色、默认/A/B、金额溢出、资源边界、完整分页和导出限制；CSV 重解析后的 ID 集合、行数与币种金额一致。

### F07 / F08：按平台接入完整报告

桌面 → 移动 Web → Android 顺序接入同一服务合同，使用共用合成夹具核对结果。移动能力守卫仅在实际入口通过后放开；Android 从 Entity 的 ID、币种和整数金额计算，不从展示文本解析。

**完成标准：**月报 → 改五维筛选 → 下钻 → 返回 → 导出预览 → 下载的生产路径通过。取消不导出，失败保留查询；离线/同步中/已完整读取分别标明，隐藏金额不经图表或辅助标签泄漏。

### F09：改造月度首页

明确展示月份和账本，提供本月收支、净额、预算进度与待处理入口；金额按实际币种分组，汇率折算若另行提供必须明确来源与时间。Android 从累计改为月度时保留可辨的累计入口，不混用余额和月度收支。

**完成标准：**首页、报告和下钻使用同一月份、时区及账本，退款符号与转账口径一致；未同步、读取失败、缺预算和真实零可区分，重试不重复记账。

## 5. 第三批：适配、发布与优化

### F10 / F11：每轮持续补齐质量门禁

- Web 覆盖 375/768/1024/1440px、100%/125% 缩放、深浅主题、最大字号、键盘、减少动态效果和至少 44px 点击目标。
- Android 覆盖窄屏/横屏、最大字体、IME、安全区、至少 48dp 目标、完整 TalkBack 听读与已录入指纹成功路径；夹具使用生产一致 Theme + Scaffold。
- 运行相关 Web/Go/Android 门禁与隔离专项，结果解析拒绝失败、跳过、缺类和截断。远程 CI 必须实际执行并记录，不以本地通过代替。
- 保持 `AgentAccessPanel`、`AISettingsPanel`、`StatementMappingPanel`、`MonthlyBudgetPanel` 的 Vite common chunk 约束；每个 Web 候选检查实际冷启动。

**完成标准：**每条发布范围内的关键流程有平台、主题、字号、方向、键盘/读屏和失败恢复矩阵；未验收项清楚列出并决定是否允许进入该次发布范围。

### F12：正式包与保留数据升级

先冻结发布范围、源码、构建参数、版本和候选哈希，再验证 Windows 正式安装包、Android 签名包及 Web/PWA 实际入口。

真实目标按既有授权执行：先检查实际容器、镜像、端口、环境、版本和挂载，备份数据库与附件，保留旧镜像/容器；沿用真实挂载并验证 SQLite 完整性、数据/附件一致性、健康接口、前后端版本、实际静态资源及浏览器冷启动。回退必须核对迁移后的数据库兼容性，不能只替换镜像。

主 Android 安装仅使用 `install -r`，升级前后验证当前实际数据，不以历史四条流水作为门禁。遗失账本恢复单独处理，依赖原服务器登录态或用户明确确认，不凭截图重建。

**完成标准：**正式签名/安装、保留数据升级、实际部署和回退均有记录；交接包含目标、版本、备份、恢复方式及剩余项。独立 QA 包通过不等于主应用已升级。

### F13：基线驱动的性能与结构优化

使用合成 1k/10k/50k 流水测请求数、首屏时间、筛选耗时和内存；Android 增加同步时长和帧/内存证据，OCR 测 1/2/4 并发延迟及峰值内存。根据瓶颈选择服务端分页/筛选、列表虚拟化、增量同步或有界 OCR 排队。

工作台、设置和 Android 导航逐条流程拆分，保留路由与恢复合同；基础部署允许不配置 AI/OCR仍可记账。通知、小组件和更多装饰性功能在核心合同稳定后评估。

**完成标准：**同一设备、数据规模和步骤的前后对照说明收益与代价；完整性、删除标记、身份隔离和重试门禁仍通过，不使用部分数据换取表面性能。
