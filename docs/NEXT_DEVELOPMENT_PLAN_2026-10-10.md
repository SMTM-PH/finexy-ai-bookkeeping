## 4. 第一批：Android AI 与待处理入口

### F03：可靠数据层

1. API 草稿编译问题已修复，账本能力检查、严格响应解析和完整分页已有专项；拒绝坏响应、重复游标、错误账本及不完整回执，不将异常当作空列表。继续在持久层中实现旧服务能力缺失时保留请求并可见提示，不回退到旧 `resolve` 路径。
2. 队列、原始来源/编辑草稿、不可变创建/确认请求与明确回执分别持久保存。隔离键包含服务器、用户、账本；默认个人账本 `0` 保留语义。金额保留退款负号和转账双金额，ID 不经浮点转换。
3. Room 变更新增向前 migration，同步备份 schema 和旧备份导入测试。旧队列的归属与确认状态先核对，不将缺失归属推断为当前共享账本。
4. Repository Flow、SyncEngine 与 WorkManager 接通同一状态合同。确认前保存稳定键和原请求；丢回包仅重试原快照；明确回执先保存，刷新失败只重新读取。迁出旧“普通新增后标记完成”路径，防止与新 Worker 重复投递。
5. 增加数据/迁移/备份、默认/A/B 隔离、四角色、降权、退款/转账、101 条分页、坏响应和丢回包专项。进程恢复必须 prepare → instrumentation 退出并终止 App → 新 PID Worker → verify。

**完成出口：**相关构建/lint、存储兼容、隔离 HTTP 和新进程专项都有完整结果；重复创建/确认仍只有一个条目/一笔财务入账，余额变化一次。API 模型或编译通过不能完成 F03。

代码入口：[API](../android/app/src/main/java/com/finexy/mobile/data/FinexyApi.kt)、[数据库](../android/app/src/main/java/com/finexy/mobile/data/FinexyDatabase.kt)、[备份](../android/app/src/main/java/com/finexy/mobile/data/LedgerBackup.kt)、[同步](../android/app/src/main/java/com/finexy/mobile/data/SyncEngine.kt)。[模板 Worker](TEMPLATE_CREATION_ANDROID_WORKER_2026-10-05.md) 可复用恢复模式，不能直接视为 AI 已验收。

### F04：生产来源与复核页面

- 当前账本文字、手动粘贴、图片统一进入来源流程；读取剪贴板不自动发模型。图片裁剪、旋转和真实预览提供可访问操作，原图与来源的保存、丢弃和清理有明确合同。
- 明确“发送识别”“保存待复核”“确认入账”三个动作。识别结果标记为建议，未匹配账户/分类保持待选择，不静默填首项。
- 保留原始金额表达式、日期/时区和完整字段；使用当前账本真实字典。加载、空态、失败、冲突、权限变化、未知结果和已知回执分别可见。
- 复核、预览、确认、忽略、恢复和删除按角色执行。Activity 重建、进程重启、账号/服务器/账本切换和迟到响应不得串账或丢输入。

**完成出口：**独立 QA 包或专用环境的生产页面断言、UI 树和截图通过；所有者、管理员、普通成员、只读成员符合服务端权限合同；相关旧 AI、同步和模板回归通过。

### F05：当前账本待处理入口

首页分别显示 AI 待复核、周期待确认和同步失败；失败计数不显示为零。条目移出队列但本机回执未核对时仍可恢复；点击定位原账本、原条目，权限变化后重新检查。通知不直接改变余额。

**完成出口：**真实空态、失败重试、账本切换、迟到响应、隐藏金额、确认后刷新和通知深链通过；尚未接通的端保留明确能力限制。

## 5. 第二批：报告、导出与月度首页

### F06：统一查询与服务端合同

首版交付“当前账本五维只读月报与明细 CSV”。日期、类型、账户、分类、标签使用一个规范化查询；账本、币种和展示时区为明确上下文。图表、合计、列表、下钻和导出使用同一范围。

- 自然日转换为 `[start, endExclusive)`，覆盖跨年、月末和 DST；API 秒与 Room 毫秒仅在边界转换。
- 按实际资源 ID 和归属处理，不按名称合并。流水包含多个标签时，分组合计不可直接相加。
- 收入、支出和退款按原币整数汇总；转账按逻辑流水去重、保留两侧但不计入收支，余额调整单列。溢出、缺元数据或未读完分页显式失败。
- CSV 预览绑定查询与数据基线，列明条数、币种和合计；身份、过滤或数据变化后重新核对。处理公式开头文本及逗号、引号、换行，保留账号备份导出的独立兼容合同。

**完成出口：**CGO=1 专项和无卷隔离 HTTP 验证默认/A/B、四角色、权限撤销、分页、溢出、时区及导出限制；CSV 重解析后的 ID 集合、行数和原币金额等于查询结果。

### F07 / F08：跨端报告

先桌面，再移动 Web，最后 Android，使用同一组合成夹具。Android 从 Entity 的 ID、整数金额和币种计算，不解析展示文本；移动共享报告的能力守卫在生产入口验收后开放。

**完成出口：**月报 → 五维筛选 → 下钻 → 返回 → 导出预览 → 下载/分享完整路径通过。离线快照、同步中和完整在线结果区分；取消无导出，失败保留查询，隐藏金额不从图表或辅助标签泄漏。

### F09：明确月份的首页

提供月份/账本选择、本月原币收支与净额、预算进度、待处理和报告入口。预算按月份、账本、币种核对；累计数据如保留，应有单独明确入口，余额与月度收支不混用。

**完成出口：**首页、报告、下钻的月份、时区、退款和转账口径一致；未同步、读取失败、缺预算、真实零可区分；保留账户卡片交互及真实金额/状态。

## 7. F13 优化方案与延后项

| 优化方向 | 修改前测量 | 优先方案与验收 |
| --- | --- | --- |
| 列表与报告 | 合成 1k/10k/50k 流水，测请求数、首屏、筛选耗时和内存 | 按瓶颈采用服务端筛选/分页、索引或虚拟列表；保证完整统计和导出 |
| Android 同步 | 同设备测同步时长、请求数、帧和内存 | 有界批次与增量读取；保留删除标记、请求快照、幂等和账号隔离 |
| OCR | 1/2/4 并发延迟、失败率与峰值内存 | 按测量采用有界队列；未配置 AI/OCR 的基础部署仍可记账 |
| 组件与状态层 | 识别重复状态转换、超大组件及循环依赖 | 逐条流程拆分；复用来源会话、持久恢复和查询合同，保留路由/行为回归 |

各项提供同设备、同数据、同操作的前后对照及代价，目标阈值在取得基线后确定。汇率折算、资产估值、PDF/Excel、高级 AI 分析、新 Tab、小组件及更多装饰效果先不列入首版报告交付；后续评估不缩减必要正确性与发布工作。
