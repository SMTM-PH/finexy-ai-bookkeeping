## 3. 第一批：Android AI 完整流程

### F03：补齐原图加密持久恢复

已有 Room 请求、回执和 Worker 不重做。下表数据层已由 [原图专题](AI_REVIEW_ANDROID_IMAGES_2026-10-19.md) 完成专项；生产导入、裁剪/识别和活动恢复仍须与 F04 一起验证，不把存储 API 的通过泛化为实际来源页完成：

| 子项 | 实施内容 | 验收条件 |
| --- | --- | --- |
| F03-1 存储合同 | 原图、裁剪/旋转参数、识别结果绑定同一来源草稿及版本；按服务器、用户、账本隔离；明确大小、格式与像素限制 | 进程退出后恢复同一原图与预览；损坏、超限、缺失可见，不用空图或零值代替 |
| F03-2 加密与引用 | 设计密文、密钥保护和引用校验；保留原图与发送用派生图片的区别；不在日志或普通草稿字段保存明文图片 | 无法跨身份/账本置换读取；持久存储不残留未约定的明文副本；密钥失效有明确恢复/失败行为 |
| F03-3 生命周期 | 明确保存、替换、丢弃、创建请求冻结、回执核对和清理规则；防止旧异步保存及清理删除较新版本 | 未完成原请求所需来源仍可恢复；终态清理只影响相应引用；中断或失败不留下不可恢复草稿 |
| F03-4 迁移与备份 | 若增加 Room 表/字段，新增向前 migration；扩展备份及旧版兼容；明确跨安装恢复图片和受保护密钥的方案 | 旧流水/模板/队列完整；新旧备份可按合同读取；恢复后图片可解密，不能仅恢复失效路径 |
| F03-5 进程恢复 | 使用持久草稿与原请求接续；不靠内存 Bitmap；已知回执只读，未知结果重放原快照 | prepare → 退出 instrumentation 并终止 App → 新 PID Worker → verify；不重复创建/确认，不覆盖新输入 |

本轮采用 Room 分块密文与密码备份内可迁移内容，已增加 25→26 migration 和 schema 20；后续再变更仍新增迁移。数据层专项与实际生产来源流程的全部出口均通过后，才能关闭 F03。

代码入口：[AI 持久层](../android/app/src/main/java/com/finexy/mobile/data/AIReviewPersistence.kt)、[数据库](../android/app/src/main/java/com/finexy/mobile/data/FinexyDatabase.kt)、[备份](../android/app/src/main/java/com/finexy/mobile/data/LedgerBackup.kt)、[同步](../android/app/src/main/java/com/finexy/mobile/data/SyncEngine.kt)。

### F04：接入生产来源、复核与确认

当前已存在 [来源页面](../android/app/src/main/java/com/finexy/mobile/LedgerAISourcePage.kt)、[来源会话](../android/app/src/main/java/com/finexy/mobile/data/AIReviewSourceSession.kt)、[复核队列](../android/app/src/main/java/com/finexy/mobile/LedgerAIReviewPage.kt) 和 [原子确认编辑器](../android/app/src/main/java/com/finexy/mobile/LedgerAIReviewEditor.kt)。后续针对下列合同补齐与验收，不将“有源码”标为“已交付”。

1. **来源页面**：文字、手动粘贴、相册/拍照进入当前账本同一流程。展示接收方和明确发送动作；读取剪贴板不自动发送。图片可裁剪、旋转、预览、保存和丢弃，提供可访问操作。
2. **动作分离**：“发送识别”得到建议，“保存待复核”创建队列，“确认入账”才改变财务数据。使用当前账本字典；同名歧义和未匹配账户/分类保持待选择，不默认首项。
3. **完整编辑**：保留原始金额表达式、日期/时区、币种、标签、备注及其他既有字段；覆盖退款负支出、内部/外部转账双账户和双金额。预览与提交绑定同一编辑版本。
4. **生产写入迁移**：调用可靠创建与原子确认，迁出旧“普通新增后 resolve”链路；核对旧入口、编辑器、Worker，避免两条链路重复入账。旧服务能力缺失时保留输入与请求并可见提示。
5. **队列与权限**：列表、详情、确认、忽略、恢复和删除按既有服务端合同执行；所有者、管理员、普通成员、只读成员分别验证，提交时重新核对权限。
6. **恢复与状态**：区分加载、真实空态、失败、冲突、降权、未知结果及已知回执。Activity 重建、进程退出、换用户/服务器/账本及迟到响应均不串账、不覆盖新草稿。

7. **图片接口实时配置**：服务启动时图片能力关闭，运行中开启后无需重启即可调用；关闭后立即拒绝且不调用模型，文字识别不受影响。路由注册修复已在新候选通过 8 项 HTTP 及 Android 图片页面专项，后续改动保留相关回归。

验收采用独立 QA 包中的生产页面、UI 树、截图、功能断言及真实隔离 API。覆盖默认账本 `0`、共享 A/B、四角色、分页、坏响应、丢回包、较新输入和权限撤销；补旧 AI、模板与同步关联回归。API 测试或调试宿主不能替代生产页面验收。

代码入口：[AI 页面](../android/app/src/main/java/com/finexy/mobile/AIReviewScreens.kt)、[主入口](../android/app/src/main/java/com/finexy/mobile/MainActivity.kt)、[API](../android/app/src/main/java/com/finexy/mobile/data/FinexyApi.kt)。界面实施前完整阅读 [UI/UX 基线](UI_UX_DESIGN.md)，继续沿用现有风格与组件。

### F05：待处理入口

首页和已有入口分别呈现 AI 待复核、周期待确认、同步失败；失败不能显示成零。共享同一状态来源，点击定位原账本/原条目；已移出队列但本机回执未核对的请求仍可恢复。通知只导航，不能直接入账。

验收覆盖真实空、读取失败、重试、换账本、迟到响应、确认后刷新、隐藏金额和通知深链；不能读取的原账本给出可见状态，不自动换到其他账本继续操作。

## 4. 第二批：报告、导出与月度首页

### F06：先统一查询与服务端口径

首版范围为“当前账本五维只读月报与明细 CSV”。依据 [报告范围审计](REPORT_SCOPE_AUDIT_2026-10-04.md) 在当前源码复现风险，再实现规范化查询；历史源码审计不是本轮运行结果。

- 日期、类型、账户、分类、标签为五维；服务器、用户、账本、IANA 时区和币种规则为明确上下文。图表、合计、列表、下钻与导出共同使用该查询。
- 自然日转为 `[start, endExclusive)`，覆盖跨年、闰日、月末和 DST；API 秒与 Room 毫秒仅在边界转换，不用固定 24 小时推算自然日。
- 原币整数汇总，保留退款负号；转账按逻辑流水去重并保留两侧，不计入收入/支出；余额调整单列。缺元数据、溢出和未读完分页显式失败。
- 账户/分类按实际 ID 与归属，父级展开校验；同名不合并。标签只开放当前账本可读范围；多标签组的合计不可直接相加，读取不新增管理权限。
- CSV 预览绑定查询与数据基线，展示条数、币种和合计；身份、过滤或基线变化后重新核对。处理引号、逗号、换行和公式开头文本，明确整数单位与展示单位。
- 当前报告导出与既有账号备份导出分别保留合同。四角色读取及现有导出限制在服务端落实，不能仅依靠前端守卫。

完成条件：CGO=1 专项和无卷隔离 HTTP 验证通过；CSV 重解析的 ID 集合、笔数、原币金额与同一查询完全一致。夹具覆盖默认/A/B、四角色、撤权、超过一页、同秒多笔、混币、退款、双金额转账、隐藏记录、时区、坏响应、超限和特殊文本。

### F07/F08：跨端报告完整路径

先桌面，再移动 Web，最后 Android，复用同一组合成数据及期望结果。保留原有统计/导出兼容性；共享入口通过实际权限与页面验收后再开放。

| 平台 | 主要改动 | 验收出口 |
| --- | --- | --- |
| 桌面 Web | 统一筛选状态、月报/趋势/分类排行、明细、下钻和导出；旧深链明确迁移或兼容 | 生产浏览器完整路径，返回保留查询；图表与明细同范围 |
| 移动 Web | 当前账本报告状态与字典隔离，窄屏筛选、可见重试、导出预览与下载 | 共享四角色、深链、账本切换和慢响应；通过后调整能力守卫 |
| Android | 从 Entity 的 ID、整数金额、币种计算，替换展示文本解析；明确离线快照/同步中/完整在线来源 | 真实文件写出/分享、取消和失败处理；退款、混币、DST、最大字号与当前账本字典 |

共同路径为“月报 → 五维筛选 → 数字/分类下钻 → 返回 → 导出预览 → 下载/分享”。取消不导出，失败保留查询；隐藏金额不能通过图表比例、DOM/辅助标签或确认文案泄漏。文件下载成功不足以证明内容正确。

### F09：月度首页

统一月份/账本选择、本月原币收支与净额、预算进度、待处理和报告入口。预算按月份、账本、币种核对；累计数据若保留应另设明确入口。首页、报告和下钻使用相同时间及财务口径，保留账户卡片与金额显隐交互。

完成条件：跨月/跨年、退款/转账、混币、未同步、读取失败、缺预算与真实零均可区分，首页数字可通过对应明细核对。各端分别记录通过范围。

| 本地门禁 | 相关 Web/Go/Android 检查；SQLite/事务用 CGO=1；Agent/MCP 变更补对应脚本；缺参数、跳过、缺类或日志截断不计通过 |

## 6. F12：正式安装、升级与部署

1. **候选准备**：冻结版本与发布范围，完成所需功能、兼容、人工与 CI 门禁，生成 Windows 安装包及 Android 签名包；凭据不输出或提交。
2. **升级演练**：隔离副本验证旧版 → 新版、数据库迁移、备份恢复、保留数据与附件。Android 原位升级，不卸载、不清主数据；QA 包安装不等于主包升级。
3. **真实目标盘点**：执行前读取当前服务镜像、端口、环境、挂载、前后端版本和已安装版本，不能照抄历史容器名。真实写入和部署按已有授权执行。
4. **备份与实施**：备份真实数据库和附件，核验可恢复性；保留旧候选和原配置，完整沿用必要挂载及运行参数，不向真实账本注入合成数据。
5. **上线验证**：SQLite 完整性、原财务数据/附件一致性、健康接口、前后端版本、静态资源、浏览器/应用冷启动及实际入口。HTTP 200、文件哈希均不能单独作为完成证明。
6. **回退演练与交接**：判断 schema 是否可逆；必要时恢复匹配的数据库与附件备份，不能只切旧镜像。记录目标、版本、步骤、检查结果和未运行项。

全部 ADB 命令显式 `-s emulator-5554`，安装仅 `install -r`。禁止在主账本 AVD 运行 `connectedDebugAndroidTest`；优先独立 QA 包或专用环境。涉及安装/运行后只读冷启动核对主应用与 logcat。

历史四条流水未恢复是独立数据恢复事项，不作为当前升级数量门禁，也不凭截图重建；恢复需要原服务器登录态或用户明确确认。文档生成不附带真实部署。

## 7. F13：优化方案

| 方向 | 修改前基线 | 按瓶颈选择的方案 | 必须保留的合同 |
| --- | --- | --- | --- |
| 列表与报告 | 合成 1k/10k/50k 流水，请求数、首屏、筛选耗时、峰值内存 | 服务端过滤/分页、合适索引、虚拟列表 | 全范围统计与导出，不把已加载页当全集 |

| 页面与状态层 | 重复状态转换、组件规模、循环依赖及任务操作成本 | 每次提取一条完整业务流程、复用状态和查询合同 | 路由、原始草稿、键盘行为、财务规则与冷启动 |
