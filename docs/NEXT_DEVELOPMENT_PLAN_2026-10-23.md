### 批次 C：待处理入口与 Android 报告

F05 先统一各队列的状态含义、当前账本计数和条目定位，再连接首页/通知。同步失败、未知结果与未核对回执保留恢复入口，读取失败不能计为零；通知只导航，不能直接入账。原账本不可读时说明原因，不自动换目标继续操作。

当前 Web 实现保持三个分组、十一项来源独立状态；同一 AI 条目、原请求及关联草稿去重，但保留恢复入口。只有全部适用来源读取成功才显示完整总数，否则显示已知数量与待核验。服务端队列完整分页，超过有界上限明确失败。只读的已入账流水不算待办，普通新增已有回执只 GET 原结果，不再次 POST。

下一批按下列顺序验收：

1. Web：冻结候选，运行全量类型、lint、单测和构建；在无卷临时服务上从真实首页/通知创建和打开待处理，核对 A/B/0、独立失败与计数去重。

3. Android 报告：先完成真实 HTTP 测试代码和生产页面绑定。页面每次进入、账本/账号/服务/查询变化及退出均正确 bind/invalidate/close；同账本重新进入也不能继续使用旧预览。

## 4. 本批技术落点与限制

- 报告查询使用 IANA 时区的自然日范围；UTC 半开区间由服务端确定，不以固定 24 小时推算跨 DST/跳日日期。
- ID、金额、Unix 秒和交易序号在 Web 保持十进制字符串。合计与 CSV 校验用 `BigInt`，两位小数展示不经过浮点；不自动折算不同币种。
- 服务端先读取完整有界快照再分页，`dataComplete` 与当前页面明细完整性分开。超限明确失败，不把截断结果当完整报告。
- MySQL 除 RR/SERIALIZABLE 外，还要求显式参与表均为 InnoDB，并在同事务持有元数据锁以避免检查期间换表引擎；无白名单或非事务表明确拒绝。PostgreSQL 使用只读可重复读事务。
- 共用夹具位于 [testdata/ledger_report](../testdata/ledger_report/README.md)，现含 19 组筛选期望；包含三组精确无分类条件，三库服务层、完整应用各开启导出轮及两端浏览器已实跑。关闭导出轮只验证 2 项开关/路由合同，不能计成 19 组筛选。最终前端运行时的关联门禁另记，不用旧静态资源代替。公开 API 能创建的基础调整为目标/差额均 `1000`；历史目标 `1000`、差额 `-400` 单列变体，不宣称该状态由 HTTP 创建。
- 客户端报告与预览只在内存中保留。切账号、服务器、账本或查询时作废；导出必须当前预览、明确确认，包含隐藏金额时另行确认。

## 5. 门禁与交接

| 变更范围 | 必需验证 | 不能替代的验收 |
| --- | --- | --- |
| 纯文档 | 内容、状态、相对链接和 diff | 不附带构建、升级或部署 |
| Web 报告合同 | `npm run check`、共享夹具、分页/身份/预览/CSV 专项 | 两端生产页面、实际浏览器冷启动与文件下载 |
| Go 报告/数据库 | 全量 Go、CGO SQLite、真实 PostgreSQL/MySQL、隔离 HTTP 与权限变化 | 真实服务部署与生产规模表现 |
| Android | Java 17 下相关构建/lint/单测，设备恢复后隔离 QA 专项 | 系统入口、跨进程页面、读屏、真实文件分享和主应用升级 |
| 正式交付 | 远程 CI、签名/版本、数据与附件备份、升级、冷启动和回退 | 历史镜像或仅健康接口不能证明当前发布可用 |

每批交接必须标明已实现、实际运行、跳过、未覆盖和未部署项，记录源码/夹具/二进制/静态资源及证据位置。本机 `artifacts/` 通常不随 Git 分发，跨机器交接需另附脱敏汇总；不输出凭据或真实财务内容。

报告基础详情见 [API 与 CSV](REPORT_API_EXPORT_2026-10-22.md)；本批数据库与 Web 合同证据见 [三库与 Web 客户端合同](REPORT_PROVIDER_WEB_CONTRACT_2026-10-22.md)。
