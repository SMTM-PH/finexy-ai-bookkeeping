### 设计判断与优先取舍

| 当前设计 | 已有价值 | 下一步处理 |
| --- | --- | --- |
| Go 服务统一账本、角色与原子写入；Web/Android 独立客户端 | 业务边界可集中复核，各端保留合适交互 | 先补跨端合同和完整流程，不各自计算另一套报告/余额 |
| Android Room + SyncEngine + WorkManager，Web 持久请求与回执 | 支持原请求接续、已知回执只读和断线恢复 | 补系统入口、跨进程生产页面与未知旧记录处置；数据层通过不能替代页面通过 |
| 报告完整有界快照、分页明细、签名预览与实际文件校验 | 合计、图表、明细及导出可核对同一范围 | 维护已验三库及两端基线，接通 Android 生产流程，再用规模测量决定索引/渲染优化 |

## 4. 本批技术落点与限制

- 报告查询使用 IANA 时区的自然日范围；UTC 半开区间由服务端确定，不以固定 24 小时推算跨 DST/跳日日期。
- ID、金额、Unix 秒和交易序号在 Web 保持十进制字符串。合计与 CSV 校验用 `BigInt`，两位小数展示不经过浮点；不自动折算不同币种。
- 服务端先读取完整有界快照再分页，`dataComplete` 与当前页面明细完整性分开。超限明确失败，不把截断结果当完整报告。
- MySQL 除 RR/SERIALIZABLE 外，还要求显式参与表均为 InnoDB，并在同事务持有元数据锁以避免检查期间换表引擎；无白名单或非事务表明确拒绝。PostgreSQL 使用只读可重复读事务。
- 共用夹具位于 [testdata/ledger_report](../testdata/ledger_report/README.md)，现含 19 组筛选期望；包含三组精确无分类条件，三库服务层、完整应用各开启导出轮及两端浏览器已实跑。关闭导出轮只验证 2 项开关/路由合同，不能计成 19 组筛选。最终前端运行时的关联门禁另记，不用旧静态资源代替。公开 API 能创建的基础调整为目标/差额均 `1000`；历史目标 `1000`、差额 `-400` 单列变体，不宣称该状态由 HTTP 创建。
- 客户端报告与预览只在内存中保留。切账号、服务器、账本或查询时作废；导出必须当前预览、明确确认，包含隐藏金额时另行确认。
