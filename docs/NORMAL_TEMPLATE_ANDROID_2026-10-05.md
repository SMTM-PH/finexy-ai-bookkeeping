# Android 当前账本普通模板接续

日期：2026-10-05。此记录接续 [移动周期](PERIODIC_MOBILE_ANDROID_2026-10-05.md)，仅记录本轮源码、独立 QA 安装与隔离验收。主应用及真实服务没有升级。

## 本轮实现

- 设置 → 流水模板二级页绑定打开时的账本、服务器和用户。Room Flow 按账本读取普通模板，支持查看隐藏项；错误、加载、真实空列表与只读状态分别展示。模板管理限所有者/管理员，成员可应用，查看者没有管理和应用按钮。
- 套用先复核实时角色、模板与当前账本账户/分类，再生成独立的新流水草稿；不会以缺少服务端 ID 的模板草稿调用修改接口。确认保存前不改变余额，确认后共享新增进入既有持久写入队列，沿用稳定 `localId`。
- 新草稿保留实际币种、整数金额、双账户/双金额、分类 ID、备注、标签和隐藏金额。结构化流水卡片按实际币种显示，两侧币种独立；单笔隐藏金额和首页全局隐藏同时生效，不再写死为本地钱包。退款保持负支出；同币种转账两侧金额相等，跨币种转入金额独立。零金额模板可保存，但套用后须填写有效金额才能记账。
- 同名分类按显式 ID 和父级选择，不以名称反查首个分类。隐藏/无效父级、错类型分类、重复 ID、不完整及跨账本资源响应被拒绝。
- 非所有者套用含所有者标签的模板，必须明确选择去除标签后继续或取消；编辑模板则保留原标签关联。原模板不会因套用改变。
- 当前服务的共享流水列表不返回完整标签关联；共享编辑因此先读取带附件的真实详情，再复核对象、账本和可编辑状态。详情携带标签、附件、位置、隐藏金额与日期，避免仅凭列表构造修改请求。迟到详情不得打开另一账本的编辑器。

主要源码：`NormalTemplateScreens.kt`、`data/NormalTemplateContract.kt`、`MainActivity.kt`、`FinexyScreens.kt`、`data/FinexyApi.kt`、`data/PeriodicContract.kt`、Repository/DAO。新增查询及写入 DTO 复用现有字段，仍为 Room 23、备份 schema 17，无新数据库迁移。

### 下一步：模板创建的持久幂等与恢复

第二轮审计时，Android `FinexyApi.createTemplate` 未携带创建键；服务端 `TemplateCreateHandler` 的去重仍由内存 DuplicateChecker 保存，且在创建事务后写入。后续已补齐服务端持久回执，并通过丢回包、重启、双服务进程及删除重放验证，见 [模板创建恢复](TEMPLATE_CREATION_RECOVERY_2026-10-05.md)。Android 持久队列与草稿恢复尚未接通；不能将第二轮静态审计或后续服务端通过写成客户端恢复完成。

后续必须一起完成：

1. 服务端在模板所有者分片和创建事务内保存用户、目标账本、稳定键、不可变请求 hash 与结果 ID；同键同内容返回原结果，同键不同内容拒绝，删除后重试不得重建模板；仍复核实时成员权限。此项已形成上述冻结候选，真实服务未升级。
2. Android 在请求前持久化模板草稿和用户已确认的不可变请求，按服务器、用户及账本隔离。新增 Room migration，更新备份新旧兼容；结果未知锁定原请求，已确认成功先保存 ID，刷新失败只重读，不重新新增。
3. 以无卷服务验证并发、丢回包、服务重启、原对象删除和键内容冲突；Android 必须 prepare → instrumentation 退出并终止 QA App → 新 PID Worker → verify，覆盖权限撤销、A/B 账本切换和备份恢复。未确认草稿不能由 Worker 自动保存。
