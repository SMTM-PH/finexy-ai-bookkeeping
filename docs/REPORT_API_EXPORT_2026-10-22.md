# 当前账本报告 API、分页与 CSV

日期：2026-10-22。承接 [查询规范化](REPORT_QUERY_FOUNDATION_2026-10-20.md)、[账本快照与聚合](REPORT_LEDGER_SNAPSHOT_2026-10-21.md) 和 [后续计划 F06](NEXT_DEVELOPMENT_PLAN_2026-10-20.md)。本批接通报告 HTTP 接口及确认下载，SQLite 候选已完成隔离专项；跨数据库与生产客户端继续接续，F06 和整个计划尚未关闭。

## 接口与调用顺序

所有接口均要求正常登录会话，响应使用 `Cache-Control: no-store`。本批没有扩大已有 API/MCP 令牌的 allowlist；令牌绑定账本、AI 私有标签及管理权限继续按原合同执行。这里的令牌能力边界不表示账本成员无权读取报告，四种有效成员角色均可通过正常登录会话使用。

| 接口 | 方法 | 用途 |
| --- | --- | --- |
| `/api/v1/reports/query.json` | POST | 完整数据集聚合及分页明细 |
| `/api/v1/reports/export/preview.json` | POST | 重新核对完整快照，返回导出预览及签名凭据 |
| `/api/v1/reports/export.csv` | POST | 明确确认后核对凭据、当前快照及权限，再返回 CSV |

[处理器](../pkg/api/ledger_reports.go) 与 [生产路由](../cmd/webserver.go) 已接入。旧统计、账号导出和备份接口保留原语义，新接口不替换这些用途。

查询示例仅表示请求结构，不包含真实账号或账单：

```json
{
  "query": {
    "ledgerId": "0",
    "startDate": "2026-10-01",
    "endDate": "2026-10-31",
    "timezone": "Asia/Shanghai",
    "types": [1, 2, 3, 4],
    "hidden": "exclude"
  },
  "offset": 0,
  "count": 50
}
```

请求必须为 JSON，限制 1 MiB；拒绝重复字段（含嵌套、大小写等价字段）、未知字段、过深结构、非法类型或多段 JSON。账本及资源 ID 必须为规范的 int64 十进制字符串，不能提交 JS 数字。筛选和自然日合同见规范化专题。

## 聚合与分页

服务端先取得完整、有界的匹配集合，再生成所有合计、分组及 hash；分页只切分明细。返回 `dataComplete: true` 表示聚合来源完整，`detailsComplete` 表示该响应是否包含全部匹配明细，不能混用这两个字段。

- `matchedCount` 是完整逻辑流水笔数；内部转账仅计一笔，保留双侧物理 ID。
- 默认每页 50，允许 1–200；显式 `0`、负数或超限会失败，不静默纠正。
- 后续页必须携带前页 `expectedSnapshotHash`；基线不同返回 409。`nextOffset: null` 表示结束，不能只按当前页数量判断完整性。
- 每页的规范化查询、hash、合计与分组使用同一完整基线。客户端不得再拿当前页重算月度总额。
- 请求人、角色、查询、匹配数据或所用资源名称变化会影响快照 hash。ID 不变但标签改名，也需重新核对。
- `exportAllowed` 反映当前全局导出开关与用户导出限制；读取报告不会因只限制导出而失败。

[分页与 CSV 实现](../pkg/services/ledger_report_export.go) 不修改原快照。真实空结果返回零笔、空集合和可核对的空文件，不以读取失败代替真实空态。

## 预览与确认下载

预览请求包含原查询及当前 `expectedSnapshotHash`。服务端重新读取同一范围，核对基线、当前角色及导出许可；成功返回规范化查询、完整笔数、各币种整数合计、隐藏金额范围、到期时间和 `previewToken`。

签名凭据有效期为 10 分钟，绑定实际用户、登录会话、请求主机和完整快照；使用独立的报告签名域，不是登录凭据，也不授予任何额外权限。客户端只在当前导出会话内保存，不将其写入日志或长期偏好。

下载须回传原查询、`expectedSnapshotHash`、该预览凭据和 `confirmed: true`。查询包含隐藏记录时，还必须明确提交 `includeHiddenAmounts: true`。改变查询或账本不能复用旧凭据；重新登录产生另一会话、主机变化、凭据损坏或到期均要求重新预览。

下载时重新取得完整快照，并与已确认基线比较；CSV 始终从这份已核对快照生成。文件生成后再检查当前账本访问、角色、全局导出开关、用户限制及凭据有效期，检查失败不返回文件字节或附件头。正常的重复下载允许复用尚有效且基线未变化的确认，不产生财务写入。

读取和下载的关键验证点均重新检查权限；后续客户端还须在异步完成前校验捕获的服务器、账号、账本和查询，不能将迟到响应展示给另一页面。

## CSV 文件合同

文件为 UTF-8，固定 37 列，一笔匹配的逻辑流水对应一条 CSV 记录；表头和正文中的换行不能当作流水条数。零笔只返回表头。文件名包含账本 ID 与起止日期，响应头同时带快照 hash、笔数及整数单位。

| 字段组 | 内容 |
| --- | --- |
| 查询与基线 | `report_version`、`snapshot_hash`、`ledger_id`、`timezone`、起止日、`hidden_policy` |
| 标识与时间 | 字符串逻辑 `id`、`physical_ids_json`、类型、Unix 秒、完整交易序号（Unix 秒 × 1000 加同秒递增位）及本地自然日 |
| 分类/人员 | 分类 ID/名称、实际记账人与付款人 ID |
| 资金双侧 | 两个账户的 ID/名称、原币种、`source_amount_minor` / `destination_amount_minor` 整数金额 |
| 调整 | `adjustment_minor` 为实际变动，`balance_target_minor` 为目标余额，二者不能混用 |
| 标签/备注 | 标签 ID/名称 JSON 数组、隐藏标记和备注 |
| 主单位 | `major_unit_scale: 2`；来源/目标金额、调整和目标余额各有对应 `*_major` 两位小数主单位列 |

主单位列遵循现有 Finexy 导出格式，由整数除法和余数生成；`MinInt64` 也不取会溢出的绝对值，不经过浮点。最小单位列供程序精确核对，`amount_unit: minor` 指这些明确带 `_minor` 后缀的整数列；主单位列则由 `_major` 后缀和小数位数字段标明。币种不折算，选择任一转账侧后保留另一侧。

使用标准 CSV 引号处理逗号、双引号和字段内换行。文本列对公式开头、前置空白/控制/格式字符及原始单引号做可逆的前置单引号保护；金额列保留真实数字符号。标签名称位于 JSON 数组字段中，不作为独立公式文本输出。不同 CSV 读取器可能将字段内 CRLF 规范化为 LF，文件本身保留原字节；测试分别核对原字节与重解析结果。

## 导出限制撤销修复

HTTP 专项发现，既有 CLI 撤销用户功能限制时，将 `uint64` 补码直接格式化为 SQL 字面量，超出 SQLite 的 int64 整数范围，导致移除导出限制后该位仍保留。本批在 [用户服务](../pkg/services/users.go) 改用有符号 int64 掩码，新增 [SQLite 回归](../pkg/services/users_feature_restriction_cgo_test.go) 核对只解除指定限制、保留其他限制、解除最后一位及再次添加。

修复后的真实 HTTP 流程通过正常登录账号及现有 CLI 设置限制：查询仍可读、`exportAllowed` 变为 false、旧导出凭据被拒绝；撤销限制后许可恢复，随后仍能正确拒绝数据基线变化的旧确认。没有通过数据库伪造令牌或绕过登录鉴权。

## 验证与交付状态

[HTTP 驱动](../.github/scripts/verify-ledger-report.mjs) 严格检查候选镜像、容器名、无挂载、自动移除及 loopback 端口；使用随机账号与合成数据。开放导出的候选通过 12 组实际 HTTP 检查，关闭导出的候选通过 2 组检查，证明相关路由始终注册并在运行时执行开关。

HTTP 覆盖四角色、A/B/默认账本、非成员、当前账本标签投影与私有标签边界、五维组合、隐藏账户历史、退款、跨币种内部及外部转账、调整、分页、损坏凭据、会话/主机绑定、明确确认及隐藏金额确认、用户限制实时变化、数据变化、降权与撤权。凭据到期、签名及长度界限另有单测，不宣称实际等待 10 分钟的 HTTP 到期路径已运行。文件重解析核对 ID 集合、笔数、各币种合计、两种单位的一致性、逗号/引号/换行和公式文本保护。

[处理器 SQLite 专项](../pkg/api/ledger_reports_cgo_test.go) 在文件渲染期间实际修改成员角色、成员状态、导出设置或用户限制，四种情况均拦截返回。权限结果来自临时数据库/当前配置，登录中间件由上述 HTTP 专项验证。关联 `.github/scripts/verify-agent-access.mjs` 的 21 组 HTTP/浏览器检查通过，包括权限隔离、并发幂等、重启、桌面和移动入口及令牌撤销；截图均在关闭完整令牌显示后生成。它是关联回归，不等于新报告客户端已经实现。

最终候选与本机证据放在 `artifacts/ledger-report-api-20261022/`；Agent 证据另存 `artifacts/agent-access/report-api-20261022/`，原同名证据先备份。源文件清单、哈希、构建版本、镜像和最终门禁以 `summary.json` 为准。前批 `20261021` 目录保留诊断结果及失败，不能当作修正后候选的完整验收。
