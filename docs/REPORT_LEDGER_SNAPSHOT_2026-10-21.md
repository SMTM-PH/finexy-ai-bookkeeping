## 实现与边界

[快照读取](../pkg/services/ledger_report_reader.go) 在所有者分片读取数据，事务内重新检查当前成员与账本状态。四种有效活动角色均可读取，默认账本 `0` 仍属于当前登录用户；A 的成员身份不提供 B 的读取权限。没有借用家庭组作为前置条件，也不写入流水、余额或财务副本。

查询日期段逐一转换成数据库的序号范围 `[Unix秒 × 1000, endExclusive秒 × 1000)`，保留同秒序号。首版最多读取 50000 条日期范围内的物理记录；每类元数据最多 20000 项。超过上限明确失败，不拿前一页生成完整报告。后续若要扩大规模，须同时改进完整读取策略并取得性能证据，不能单纯截断或抬高常量。

内部转账校验双侧所属用户/账本、互相引用、方向、分类、金额与目标记录关联，按 OUT 记录的时间归一成一笔；序号跨过日界时，会另读日期范围外的关联侧并完成校验。外部转入/转出保留缺失侧为 `null`。任一物理侧隐藏金额时，默认排除整笔逻辑转账；隐藏账户的历史流水仍保留。

[聚合内核](../pkg/services/ledger_report_builder.go) 先得到唯一匹配集合，再生成明细、原币种合计、自然日趋势、分类组和标签组。没有浮点金额或隐式换汇。

| 情况 | 固定口径 |
| --- | --- |
| 收入/支出 | 原始整数最小单位，负支出保留退款符号；净额 = 收入 − 支出 |
| 转账 | 单笔逻辑流水，保留源/目标账户、币种、双金额及物理 ID；与普通收支分列 |
| 调整 | 单列 `adjustment`，取记录中的实际变动 `RelatedAccountAmount`；`balanceTarget` 单独保留目标余额，不能把目标余额当成本期收入或变动 |
| 账户过滤 | 任一侧匹配后保留完整逻辑流水；排除模式排除任一侧命中的整笔流水；父级展开验证真实父子关系 |
| 币种过滤 | 任一侧币种匹配后保留完整双侧，因此可能同时出现其他币种的转账列；不删掉另一侧，也不折算 |
| 分类过滤/分组 | 按 ID 及合法父级展开，同名不同 ID 不合并；输出所用/所选资源及父级标签，不返回账户余额或无关分类名称 |
| 标签过滤/分组 | 沿用无标签、AND/OR 及否定模式；两侧关联去重。同一笔可进入多个标签组，返回 `tagGroupsAdditive: false`，不能将标签组合计相加当作总额 |
| 不完整/溢出 | 缺账户、分类、父级、标签或转账关联明确失败。内部用宽整数累加，最终每个返回组及净额都检查 int64 边界；不受中间累加顺序影响，不返回溢出后的零或部分结果 |

## 当前账本标签读取合同

这次增加的是专用报告读取投影。可读标签名称必须同时满足：关联记录与流水均属于账本所有者、均未删除，流水实际位于当前可读账本；再按这些标签 ID 读取同一所有者未删除的标签。没有关联到该账本的私有标签、其他账本独有标签以及其他用户标签均不进入字典，显式请求这些 ID 会被拒绝。关联指向缺失或跨用户标签时明确报不完整。

权限检查和上述投影读取在同一事务中。该合同不授予标签管理权限，不改变现有账号级标签 API，也不把报告投影交给 AI 提示词；[AI 识别合同](AI_RECOGNITION_LEDGER_2026-10-05.md) 的所有者私有标签边界继续保留。新报告入口仍需通过 HTTP 四角色与资源隔离专项后才能放开。

## 一致性与快照绑定

[只读快照事务入口](../pkg/datastore/read_snapshot.go) 在读取前确定隔离前提：SQLite 沿用项目的私有缓存和事务策略并检查未开启脏读；PostgreSQL 为当前事务设置 repeatable read/read only；MySQL 检查连接隔离级别，弱于 repeatable read 时明确失败，不改变连接池的会话或全局默认。后两种数据库的实际容器回归尚待执行，不能用 SQLite 结果代替。

PostgreSQL 的默认逐语句快照及事务设置时机依据 [官方 SET TRANSACTION 文档](https://www.postgresql.org/docs/current/sql-set-transaction.html)；MySQL 事务中修改隔离级别的限制依据 [官方 SET TRANSACTION 文档](https://dev.mysql.com/doc/refman/8.4/en/set-transaction.html)。这里的文档核对属于实现依据，不能代替运行验收。

完成原始数据读取后先释放数据库事务，再对私有副本执行分组和哈希，减少 SQLite 既有 immediate 策略下的锁持有时间。当前没有声称性能收益已测量；规模和并发基线仍属 F13。

快照 hash 绑定规范化查询、实际请求人、所有者、事务内读取的角色、匹配明细、所用/所选资源及父级名称、可读标签字典和计算结果。相同请求稳定，换用户、降权、修改数据或所用标签后变化。它仅用于相等性校验，不是凭据；分页/导出仍须重新检查当前权限、确认动作及基线。

## 验证

新增 [SQLite 专项](../pkg/services/ledger_report_cgo_test.go) 和 [整数聚合边界专项](../pkg/services/ledger_report_builder_test.go)，覆盖五维组合、四角色、默认/A/B 账本、私有标签隔离、同名分类、隐藏账户、负支出、跨币种双侧、外部转账、调整差额、跨日双记录、同秒多笔、大于 JS 安全整数的 ID、改名/降权后的 hash、损坏元数据、金额溢出、真实空与 50001 条超限。只读调用前后逐项比较账户、流水和标签关联，核对零财务写入。

本机证据目录为 `artifacts/ledger-report-reader-20261021/`，保留中间失败与修正记录、最终候选源文件哈希、CGO=1 日志、主机日志、构建与 Web 门禁；结果以 `summary.json` 为准。最初测试修正了夹具隔离、唯一邮箱及保留字表名的方言引用问题，不将诊断运行累计成通过数量。

最终冻结候选的 Linux CGO=1 全套 Go 测试通过，48 个有测试的包通过，报告/规范化/快照隔离相关 16 个顶层函数、96 个末级测试实例通过；主机 CGO=0 全套、主机/Linux 构建及 `npm run check` 均通过。主机的 SQLite Vacuum 用例按 CGO 条件跳过，Linux 本轮没有用例跳过；这些计数不与前批结果累加。临时容器和内部网络均已清理。

前批查询规范化的 Linux 全套验证已在 `artifacts/ledger-report-query-20261021/` 补验：原来的缺模板、无网卡两项环境错误已修正，使用无挂载的内部网络容器通过。它只证明前批冻结候选，不替代本批读取内核的最终验证。
