# 报告三库验证与 Web 客户端合同

日期：2026-10-22。承接 [API 与 CSV](REPORT_API_EXPORT_2026-10-22.md)，对应 [当前开发计划](NEXT_DEVELOPMENT_PLAN_2026-10-22.md) 的 F06/F07。所有财务夹具均为合成数据。

## 本批变化

### 数据库快照

在无卷、独立网络的一次性 PostgreSQL 17 和 MySQL 8.4 中运行真实数据库专项，没有用 mock 代替 provider。包括跨连接并发提交时的元数据/流水一致性、四角色、默认账本、撤权、五维筛选、原币整数合计、CSV 及共用夹具。

旧 MySQL 路径只检查 RR/SERIALIZABLE，在真实 MyISAM 表上会进入读取回调，无法保证跨 SELECT 的快照一致。修复后 `DoReadSnapshot` 接收显式表白名单；报告传七张表，末尾权限复核传账本和成员表。每张表先在当前事务打开取得元数据锁，再检查实际引擎必须是 InnoDB，无白名单、非事务表或弱隔离明确失败。

专项还逐一验证七张报告表改为 MyISAM 都被拒绝、无关 MyISAM 表不阻断合法报告，以及并发 `ALTER TABLE` 必须等待读事务结束，防止“先检查引擎、后换引擎”竞态。没有修改共享连接池的全局/会话隔离默认值。

### JSON 请求解析

重复字段检查由遍历历史字段改为 Unicode simple-fold 的索引，仍拒绝大小写、转义名称及 Kelvin K/long S 等等价重复字段。每个对象最多 64 字段，严格 schema 的未知字段检查继续保留。50,000 字段、少于 1 MiB 的反例在读取前 4 KiB 内明确拒绝；回归断言解析进度而非依赖机器速度。

### 共用财务夹具

[v1.json](../testdata/ledger_report/v1.json) 是 Go/HTTP/Web 的合成基础及独立期望，使用同一份 ID/金额字符串。现有 19 组筛选，包含三组精确无分类条件，已在三库服务层、各开启导出的 HTTP 轮及两端生产浏览器实际运行；不同阶段不累计计数。包含默认和 A/B 账本、隐藏账户、同名分类、负数退款、双币内部转账、单侧外部转账、非对称标签、下月边界及隐藏金额。

HTTP 适配器把符号 ID 映射到临时服务真实生成的 ID；金额使用 BigInt 十进制原样编码，不先转换成 JS Number。直接数据库适配器保留非对称标签和非法引用反例。公开 API 的初始调整目标/差额均为 `1000`；历史目标 `1000`、差额 `-400` 是单独显式变体，不能混为同一个 HTTP 创建过程。

### Web 客户端

实现位于 [模型](../src/models/ledger_report.ts)、[合同校验](../src/lib/ledger_report.ts)、[状态管理](../src/stores/ledgerReport.ts) 和 [下载校验](../src/lib/ledger_report_download.ts)，请求接入已有 services，账号重置接入 root store。

- 查询、响应和预览作防变更拷贝；ID/金额/秒/整交易序号保持字符串。`sequence / 1000 == time`，序号不是毫秒余数。
- 逐页校验当前查询、快照、完整源标志、计数、资源归属、字段结构、排序和分组；累计不超过 50,000 条，跨页逻辑/物理 ID 不复用，末页精确重算金额与分组。分页数据不能被当作全量合计。
- 切换账本同步清空报告和预览；换账号/服务器、reset、查询刷新和迟到响应都核对原上下文。失败不能变成零值或成功空报告。数据和导出证明不持久保存。
- 导出确认必须携带用户所见预览的 `snapshotHash` 和 `previewToken`，并与当前预览严格一致。旧弹窗不能确认后来生成的预览；隐藏金额仍需单独确认。
- 实际下载检查状态、CSV 类型、附件文件名、快照/数量/单位响应头和 UTF-8。重解析全部 CSV，验证最小/主单位金额、完整明细合同、各组汇总及已知行逐字段一致；拒绝错误 JSON、缺行、重复行、未保护的公式文本和错误转账方向。下载后的异步文件读取结束时再次核对身份。

未加载明细仅能用服务端快照证明、完整文件合同和汇总检查；已加载行必须是文件中的精确子集。全部明细加载后才能额外对照完整客户端 ID 集合。客户端不能仅凭公开 hash 独立重新计算服务端包含身份的快照签名。

生产下钻发现原分类筛选只接受正 ID，无法精确定位 `categoryId: "0"` 的调整和储蓄目标转账。现已新增类别字符串 `0` 的专用合同；账户、标签仍要求正 ID，不伪造分类资源，也不把 `includeDescendants` 的零解释为全部根分类。`category0-final` 候选全 CGO 通过，真实 PostgreSQL/MySQL 服务层覆盖 19 组；合法储蓄目标转账由真实调用存入/取出的 CGO SQLite 专项覆盖。此证据不代表后续完整应用 MySQL 启动修复已通过。

首批 16 组的真实 SQLite HTTP 已通过；后续完整应用 MySQL 启动失败，定位为预算 TEXT 列声明默认值，以及真实预算读取暴露的 `YEAR_MONTH` 保留字引用问题。修复移除 TEXT 默认声明、保留 TEXT NOT NULL，并精确引用四处查询字段；已有服务仍显式写入 `{}`，不把损坏空串修成空预算、不截短分类 JSON、不重建用户财务数据。
