## 实现范围

新增 [查询模型与规范化](../pkg/models/ledger_report_query.go)、[专项测试](../pkg/models/ledger_report_query_test.go) 和可供跨端复用的 [日期合成夹具](../pkg/models/testdata/ledger_report_dates.json)。规范化函数不访问数据库、设备或用户服务，也不赋予任何资源读取权限；当前尚未注册报告 API。

| 输入 | 本批合同 |
| --- | --- |
| 账本 | 必须显式传字符串 `ledgerId`，默认个人账本为 `"0"`；拒绝数字 JSON、负数、前导零、浮点及 int64 溢出 |
| 日期 | 严格 `YYYY-MM-DD`，起止日均包含；年份 1970–9998，最多 3660 个自然日；日期逆序或超限明确失败 |
| 时区 | 显式 IANA 名称或 `UTC`，拒绝空值、服务端 `Local` 和未知名称；内嵌标准库时区数据供离线精简镜像使用 |
| 类型 | 省略代表全部；显式非空数组仅接受 1 调整、2 收入、3 支出、4 转账；规范化去重排序，JSON 保持数字数组 |
| 账户、分类 | 非空字符串 ID 数组，显式 `include` / `exclude`，可声明 `includeDescendants`；数值排序去重，每组输入最多 1000 项 |
| 标签 | 多条匹配条件取交集；条件内支持 `any` / `all` / `notAny` / `notAll`，`none` 必须单独使用且不带 ID；省略与显式空集区分，最多 20 条条件 |
| 币种 | 省略代表未按币种筛选；显式非空三位大写 ASCII 代码数组，去重排序，最多 256 项；实际元数据和可用币种校验留在读取事务中 |
| 隐藏记录 | 默认 `exclude`，可显式 `include`；本批只固定查询语义，后续须在同一匹配集合中应用，并落实原始金额导出的明确确认 |

输出固定 `version: 1`，回显规范化选择与 `utcRanges`。ID 和 Unix 秒以字符串序列化；类型使用 `int32` 数组，避免 Go 字节枚举切片被 JSON 编码成 Base64。输出复制请求中的切片及筛选对象，原请求后续变化不会修改已捕获的查询。

## 自然日与时间边界

`utcRanges` 的每个区间都是 Unix 秒的 `[start, endExclusive)`。实现逐段求自然日期范围与时区固定偏移段的交集，不把一天固定为 24 小时，也不依赖缺失午夜的自动归一化。

12 组合成夹具覆盖 UTC 闰日、上海跨年、纽约 23/25 小时自然日、豪勋爵岛半小时切换、圣地亚哥缺失午夜、阿皮亚跳过整日及日期线两侧、圣约翰斯日期回拨的两个不连续区间。跳过的日期返回 `[]`；不连续范围保留各段，后续 SQL 必须按各段取并集，不能把整个包络当作有效范围。

测试还复现了当前 Go 标准库未来时区规则在闰年末尾返回不前进边界的情况。实现对此逐秒检查并限制最多一天；无法恢复时明确报错，避免无限循环或直接跳过潜在切换。2040 年与 9988 年长范围均有回归。

数据库的 `TransactionTime` 是 Unix 秒 × 1000 加同秒序号，并非毫秒时间；后续读取需将每段端点各乘 1000，使用下界包含、上界排除。Room 毫秒只在 Android 边界转换，本批不修改既有存储合同。

## F06 接续与验收出口

本切片只完成查询语法与时间规范化，F06 仍在进行中。以下是本切片交接时的接续顺序，已实施进展见上述 2026-10-21 专题：

1. 在所有者分片的同一只读事务中复核当前成员权限，读取完整账户、分类、标签关联及流水；校验父级展开、资源归属、上限和缺失元数据。私有标签不因通过语法校验而变成共享资源，共享字典须先落实明确读取合同。
2. 用同一完整匹配集合生成明细、趋势、分类排行与原币种整数合计；保留退款负号，内部转账校验并去重、保留双侧，调整单列，溢出明确失败。
3. 将查询、身份、实时角色、元数据和匹配流水纳入快照绑定；分页与 CSV 确认不得混入变化后的基线。导出重新检查开关和用户限制，并重解析文件核对 ID 集合、笔数、金额及公式文本处理。
4. 完成 Linux `CGO_ENABLED=1` 的事务、四角色、分片及撤权专项，再运行无卷一次性服务的真实 HTTP 验收；其后才接 F07/F08 的生产入口。

本批未执行 Android 设备验证、数据库迁移、主应用升级或真实服务部署。F03/F04 保留原待验收项，整个开发计划未完成。
