## 数据合同

- Room 23→24 只新增 `template_form_drafts`、`template_creation_queue`，不重建或清空已有财务表。两表以账本 ID、普通/周期类型为联合主键；数据库沿用 `LedgerScope` 的服务器/用户隔离。默认个人账本 `0` 保留语义。
- 草稿保存原始字符串，包括空名称、不完整金额、未选择账户；它不是可发送的模板。草稿 ID 与递增版本一起持久化，保存时比较原版本，拒绝旧异步保存覆盖新输入。
- 只有显式确认调用 `enqueueTemplateCreation` 后才形成请求。请求保存稳定 UUID、账本、类型、草稿版本和完整 API 字节快照；一个账本/类型的未决请求不能被另一个请求覆盖，也不能通过“丢弃草稿”取消已经发送且结果未知的操作。
- 发送器只遍历确认队列；失败保留原键及原快照，取消不伪装成功或失败。单个账本失败不妨碍其他确认请求。回执必须具有正整数 ID、相同账本及类型，已删除回执同样表示原创建已完成。
- 回执先持久化为 `posted`；后续读取失败不会重发。只有完整有效的同账本周期快照提交后才清理回执；周期功能不可用时保留周期回执。清理草稿必须匹配请求的草稿 ID 与版本，保留请求期间的新编辑。
- 备份导出 schema 18，增加草稿和队列；schema 8–17 的原表清单保持兼容。恢复校验作用域、字段、原始字符串、请求内容和回执状态，事务内补缺，不覆盖设备上较新的草稿或回执。

主要源码：`TemplateCreationQueue.kt`、`FinexyDatabase.kt`、`TransactionRepository.kt`、`LedgerBackup.kt`，均位于 `android/app/src/main/java/com/finexy/mobile/data/`。
