# Android 模板页面：跨进程恢复专项

日期：2026-10-05。接续 [生产表单与活动重建](TEMPLATE_CREATION_ANDROID_EDITOR_2026-10-05.md)；本轮验证普通模板已确认创建丢回包，以及普通/周期模板未确认原始草稿的生产页面恢复。

## 范围与流程

1. 独立 QA UID 通过正常注册、生产登录页进入随机账号。默认个人账本与两个显式账本各保留独立账户基线，不使用主应用或真实服务。
2. 账本 A 的普通模板保留名称前后空白、不完整双金额、明确双账户/分类、标签、备注和隐藏金额；周期模板保留不完整双金额、规则、日期、时区、账户/分类、备注和隐藏金额。预览不可确认，取消后仍留在本机；准备与恢复结束均检查服务端没有这两份未确认模板。
3. 账本 B 通过生产页面预览并明确确认普通模板。仅本机代理丢弃服务端已经成功提交的创建回包，页面保留不可变原请求和重试入口，不能新增替代请求或丢弃草稿。
4. 准备阶段退出 instrumentation，宿主确认原 PID 终止，再允许代理回包。延迟任务经 WorkManager 的真实系统任务启动，QA 探针委托生产 `SyncWorker`；必须取得不同 PID 的成功见证，再启动验证阶段。
5. 第三个 PID 打开生产页面，核对账本 B 只存在原 ID 的一份模板、双账户/双金额/标签/备注/隐藏字段正确、队列已完成；账本 A 的草稿 ID、版本和完整字符串对象哈希不变，页面逐项恢复原始值；默认账本与 B 不出现 A 的草稿。三个账本的完整账户和流水快照哈希必须保持基线。

本轮只修改非导出 QA 宿主、设备用例及宿主门禁。QA 宿主仅在独立包接收有界随机夹具命名空间，不通过 Intent 注入会话；跨阶段保留夹具，验证结束按所属命名空间与数据库清理。常规页面专项仍采用原默认清理流程。生产业务、Room 24、备份 schema 18 和版本不变。

运行入口：[跨进程页面门禁](../.github/scripts/verify-android-template-editor-process.mjs)。固定测试目标为 API 34+ 的 WorkManager 命名空间；本机使用现有 API 35 模拟器。系统任务必须同时匹配独立 QA 包、实际 Worker UUID、任务 ID 和 `androidx.work.systemjobscheduler` 命名空间。必要时只触发该任务，不强停包、不取消主应用任务。

代理只在内存转发请求；日志与摘要不保留认证、密码、请求正文或财务内容。回放必须与首次创建使用相同线上的请求内容和原模板 ID。两个阶段分别验证唯一开始、成功结束、测试数和 runner 终止码，任何失败或跳过均拒绝；协议自测另覆盖误导性的成功汇总、缺失/重复状态和错误 runner。

## 剩余边界

- 本轮范围为一个已确认普通新增请求、两类未确认原始表单及其账本隔离；不扩展为所有模板操作、身份切换或权限撤销的跨进程页面验收。周期新增队列的数据/生产 Worker 专项见 [前轮记录](TEMPLATE_CREATION_ANDROID_WORKER_2026-10-05.md)，修改已有模板的活动重建见生产表单记录。
- 页面证据采用浅色、竖屏和默认字号；完整深浅主题、最大字体、横屏、IME、TalkBack 和已录入指纹成功路径仍待验收。
- 丢回包截图中的重试状态仍展示底层网络错误；本轮证明恢复操作可用，用户可读的错误文案仍需后续优化。
- 关联回归曾实测 SQLite `ledger` 表读锁竞争导致 HTTP 500；此轮未修改服务端，重跑通过不代表消除故障。后续 [SQLite 并发专项](SQLITE_CONCURRENCY_2026-10-05.md) 已直接复现表锁并完成源码/隔离修复，真实服务尚未部署；本页冻结结果仍属于修复前候选。
- 主应用保留数据升级、签名、远程 CI、真实服务/NAS 备份迁移与发布未在本轮执行。Web 模板创建持久恢复、AI 账本合同、五维报告和月度首页继续按 [完整计划](DEVELOPMENT_PLAN_STATUS_2026-10-04.md) 推进。
