## 已实现的服务端合同

- `clientSessionId` 非空时启用持久创建回执，不依赖内存去重开关或缓存寿命。键最多 128 字节，纯空白键拒绝；空键保持旧客户端独立创建行为。
- 新增 `TemplateSubmission` 表，主键由模板所有者 UID、实际创建者 UID、账本 ID 和稳定键组成。回执只保存请求 hash、模板 ID 和创建时刻，不保存令牌或额外的财务正文。表随现有 `SyncStructs` 引导创建；真实用户数据库本轮没有迁移。
- 回执与模板在同一所有者分片、同一事务提交，模板校验或插入失败时一起回滚。相同键、相同内容返回原对象；不同内容返回参数错误。hash 覆盖名称、类型、分类、双账户/双金额、标签、备注、隐藏金额和完整周期日历/时区；生成的 ID、时刻、显示顺序与后续隐藏状态不进入 hash。标签关联顺序遵守首次提交快照，不允许修改原请求后重用键。
- 默认个人账本 `0` 与各显式账本、所有者与管理员的请求分别隔离。每次创建和重放都核验实时管理权限，并在事务内复核；成员、查看者和被撤权管理员不得利用已存在回执绕过权限。
- 重放返回该模板当前的真实对象及原 ID；若后来已编辑，原创建请求不会覆盖这些编辑。若已删除，则返回原 ID 和 `deleted: true`，不重建、不重新派发；API 同时标记不可编辑，已删除周期模板不返回未来到期时刻。列表仍不包含已删除对象。
- 同账本创建的本进程锁提前覆盖权限预读，避免本进程 SQLite 成员表读写冲突；跨进程仍由事务锁及数据库复合主键保护。API 排序值在创建事务内计算，直接服务调用既有显式排序值保持兼容。无法确定的数据库错误保留失败，由客户端重试原请求；不能换键替代。

主要源码：`pkg/models/template_submission.go`、`pkg/services/template_submissions.go`、`pkg/api/transaction_templates.go`、`pkg/services/transaction_templates.go`、`pkg/models/transaction_template.go`、`cmd/database.go`。

| 真实 API / 两个独立进程 | 9 组通过，见下述范围；没有跳过，没有写入真实服务 |

真实 API 由 `.github/scripts/verify-template-submissions.mjs` 执行，先核对候选镜像、容器名称/ID、无挂载、本机端口和 UUID。仅连接临时容器 `finexy-template-submission-e2e` 的 `127.0.0.1:18113/18114`，账号通过正常注册创建；管理员经邀请接受后由所有者提权，不绕过认证。

9 组范围：

1. 本机受控 HTTP 代理在服务端提交并完整接收响应后断开客户端连接；原请求重试只得到一份 USD/CNY 双金额模板，标签及隐藏金额保留。
2. 重启整个容器，确认主进程 PID 变化；原创建键仍返回原模板 ID。
3. 同一无卷容器内同时运行两个真实服务进程，共用容器内 SQLite 文件、使用不同 UUID Server ID `238/239`；12 个同键并发请求只产生一个结果。本轮实际没有瞬态失败；验证器只允许未决 HTTP 500 重试同一不可变请求。
4. 同键变更金额、转入金额、备注、标签、隐藏金额、名称和普通/周期类型被拒绝。
5. 创建者与默认/A/B 账本的相同键各自独立，其他账本对象不受影响。
6. 普通成员、查看者及已降权管理员无法创建或重放；实时角色由正常接口修改。
7. 删除后重试返回原对象 tombstone，不出现在活跃列表、不新建替代模板。
8. 周期模板重放保留日历与时区；时区改变拒绝，删除后没有未来到期时刻。
9. 无效资源创建回滚后可以重试原键；空键旧客户端两次明确创建仍产生两个不同模板。

每组核对默认个人账本、A、B 的完整小规模流水列表与账户快照，全部不变。内存重复提交开关明确关闭，周期自动派发明确关闭，不能以缓存或后台任务掩盖结果。

初次专项暴露 SQLite 权限预读锁冲突，已将创建锁提前；完整关联测试还发现旧服务调用默认排序值被改变，已保留该行为，仅 API 使用事务内自动排序。失败日志、构建上下文缺失入口和夹具列表数量超上限的尝试均保留，不计最终通过。
