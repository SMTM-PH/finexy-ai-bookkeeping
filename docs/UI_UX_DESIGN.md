# Finexy UI / UX 设计基线

> 当前基线：2026-11-10。适用于 Web、PWA、Windows 桌面壳及原生 Android、iOS App。任何 AI 在新增或修改界面前必须先读本文，再读取对应平台的现有实现。若本文与代码不一致，以“当前基线源码”所列文件为准，并在同一次变更中更新本文。

## 1. 设计方向

Finexy 的体验关键词是：**清晰、克制、可信、温暖、可恢复**。

- 财务数据是主角，装饰不与金额、账户、风险提示争夺注意力。
- 品牌识别来自珊瑚橙、墨黑文字、暖/冷中性表面、圆润但不过度的容器。
- 主操作明确，次操作低噪；删除、覆盖、冲突解决必须让后果可理解。
- Web 与 App 保持同一品牌和语义，不要求逐像素复制。Web 偏高密度工作台，App 偏单手操作和渐进披露。
- 不延续旧版的紫色/荧光黄主色、像素狐狸游戏化、异形切角、重玻璃拟态或持续装饰动画。

### Android 四类流水录入

- 记账页使用同一分段控件切换支出、收入、转账和余额调整，切换后只显示当前类型必需字段。
- 单账户支出将账户标为“来源账户”，单账户收入将账户标为“目标账户”；字段名称必须表达资金方向，不能只写含糊的“账户”。
- 转账先明确选择“账户间转账 / 转出 / 转入”：账户间转账显示两个本系统账户且两者不能相同；转出表示给系统外的人，只要求来源账户；转入表示系统外的人给我，只要求目标账户。内部同币种只输入一次金额并说明自动记入，跨币种必须额外输入转入金额。
- 转账分类只允许已同步、可见的末级转账分类；缺少可用分类时显示可恢复提示，不用普通收支分类代替。
- 余额调整使用“增加余额/减少余额”分段，不要求用户输入负号；持久层将减少转换为负数。余额调整不显示分类和转入账户。
- 流水列表用“转账”“余额调整”文字与独立图标表达类型，不能只靠颜色。账户详情中的转账同时归属于转出和转入账户，并按所在账户一侧计算余额。

## 3. 品牌与视觉语言

### 标志

- 主标志是珊瑚橙底的白色 `F`，Web/Android 当前视觉尺寸约 34×34。
- 标志圆角约 11；不得拉伸、旋转或增加复杂光效。
- 产品名使用 `Finexy`，中文正文中不再使用旧称“栗子记账任务系统”。

### 视觉层级

1. 页面标题、核心余额、关键结果。
2. 当前任务的主要操作。
3. 筛选、状态、分类和账户上下文。
4. 帮助文字、时间、ID、同步详情。

单个可视区域只保留一个最强主操作。珊瑚橙用于品牌、重点和当前状态，不大面积铺满普通卡片。

## 4. 色彩系统

颜色必须通过语义 token 使用。已有源码中的硬编码色是待逐步收敛的设计债，不是新增硬编码的理由。

### 跨平台核心色

| 语义 | Web | Android Light | Android Dark | 用途 |
| --- | --- | --- | --- | --- |
| Brand coral | `#F05537` | `#F05537` | `#F05537` | 标志、强调、图表主序列、焦点提示 |
| Primary action | 墨黑 `#12141A` 或品牌珊瑚 | `#CB4027` | `#CB4027` | 主要按钮；白字时使用可达对比度的深珊瑚 |
| Income/success | `#149C63` / 强调态 `#087A49` | `#16845B` | `#62D3A0` | 收入、成功、健康状态 |
| Error/destructive | `#D94040` / `#B42318` | `#B3261E` | `#FF9D91` | 删除、失败、危险确认 |
| Warning/attention | `#DC6803`（正文用 `#B25309`） | `#B25309` | `#FDB022` | 预算接近上限、待复核、即将到期、汇率缺失 |
| Ink | `#12141A` / 强文本 `#101828` | `#1A1917` | `#F5F5F6` | 标题、金额、正文 |
| Muted | `#475467`–`#687181` | `#625D57` | `#ADB2BC` | 辅助说明；不得低于对比标准 |
| Canvas | `#F1F2F6` | `#F7F5F2` | `#101113` | 页面背景 |
| Surface | `#FFFFFF` | `#FFFFFF` | `#202226` | 卡片、主容器 |
| Raised surface | `#F7F8FA` | `#EEEAE5` | `#292C31` | 筛选、分段、次级区域 |
| Border | `#DFE3E9` / `#E9EBF0` | `#C8C0B8` | `#666B75` | 分隔线、输入边界 |

规则：

- 正文对背景至少 4.5:1，大文字和非文字控件至少 3:1。
- 收入/支出不能只靠绿/红表达，必须同时显示符号、类型文字或图标。
- 警示橙同样必须搭配图标或文字，不得作为预算接近上限、待复核等状态的唯一区分手段；警示色不得替代错误红用于危险操作。
- 图表类别可扩展蓝 `#2E9BFF`、靛蓝 `#4F46E5`、紫 `#7C3AED`，但珊瑚仍为第一序列。
- Web 当前工作台以浅色为生产基线；不要仅给局部组件添加“伪深色”。Android 必须同步维护完整深浅主题。
- 模态遮罩建议 40%–60% 黑；保证前景和背景层级明确。

## 5. 字体与数字

### Web

- 中文正文：`Microsoft YaHei UI`, `Microsoft YaHei`, `PingFang SC`, `Noto Sans CJK SC`, `system-ui`, `sans-serif`。
- 默认字号 14px、行高 1.5；普通正文不低于 14px，辅助文字原则上不低于 12px。
- 禁用合成字重：`font-synthesis: none`。Windows Chrome 需检查 100% 和 125% 缩放。
- 金额和数据可使用 `JetBrains Mono Variable` / `Cascadia Mono`，启用等宽数字；正文不要使用等宽字体。
- 旧版展示字体 `ZCOOL QingKe HuangYou` 不作为现行工作台默认标题字体。
- 忘记密码页使用局部浅色主题，与浅色表单背景保持一致，不继承系统深色主题的浅色文字；标题沿用正文字体、清晰字重，输入框保留 Vuetify 浮动标签的显示/隐藏逻辑。

### Android

| 层级 | 规格 |
| --- | --- |
| Display | 36sp / SemiBold / -1.2sp |
| Headline | 26sp / SemiBold / -0.5sp |
| Title large | 21sp / SemiBold |
| Title medium | 16sp / Medium |
| Body large | 16sp / 24sp |
| Body medium | 14sp / 21sp |
| Body small | 12sp / 18sp |
| Label | 14sp / SemiBold；小标签 11sp |

金额输入使用等宽数字，但无障碍读法必须保留完整币种与正负语义。最大系统字体下允许重新排版，不允许截断核心金额或操作。

## 6. 间距、圆角与阴影

使用 4/8 基础节奏：`4, 8, 12, 16, 20, 24, 32, 40, 48`。

| 场景 | Web | Android |
| --- | --- | --- |
| 页面外边距 | 92px（宽屏），1370px 以下 40px | 20dp；设置/认证页 24dp |
| 主容器 | 30px 圆角 | 页面不额外套总卡片 |
| 卡片 | 14–22px；大型卡片 24px | 18–24dp；钱包主卡 28dp |
| 输入框 | 11–14px | 16–18dp |
| 圆形/胶囊 | `999px` | `CircleShape` |
| 卡片内边距 | 14–24px | 14–24dp，标准 PanelCard 20dp |
| 区块间距 | 18–32px | 标准 20dp |

- 阴影用于悬浮菜单、Dialog、主 shell，不用于每一张普通卡片。
- Web 主 shell 当前为 `0 18px 55px rgba(18,20,26,.1)`；高层模态可更强，但不可同时叠加重边框、重阴影和玻璃模糊。
- Android 主要通过 surface 色差和 Material elevation 建层级；不要用模糊玻璃背景承载正文。

## 7. 布局与导航

### iOS 开发基线（2026-11-10）

原生 SwiftUI 客户端位于 `ios/`。iOS 使用四项底栏，新增流水从流水页右上角进入。完整范围及服务端兼容条件见 [iOS 说明](../ios/README.md)。

| 入口 | 页面 | 本轮职责 |
| --- | --- | --- |
| 登录前 | 服务器与账号、两步验证 | 明确服务器、HTTP 明文同意、密码登录、TOTP / 恢复码；失败保留输入 |
| 总览 Tab | 当前账本、月份、账户余额、分类及流水 | 月度收支按原币种显示，分类明细与流水使用同一报告快照 |
| 流水 Tab | 当前账本、流水详情、新增表单 | 游标分页、下拉刷新、按权限在线记账和编辑删除。危险操作需要明确确认 |
| 账户 Tab | 当前账本的账户列表和详情 | 当前余额与历史月份分开展示，账户流水以原币种显示 |
| 设置 Tab | 服务器与账号、显示偏好、退出登录 | 展示实际会话归属，切换服务/账号须先退出；退出清除此设备会话 |

- 使用 `NavigationStack`、`List`、系统 Sheet 和 SF Symbols，正文/背景使用系统语义色，品牌与主操作沿用珊瑚 token。支持深浅主题、Dynamic Type、至少 44pt 点击目标及安全区。
- 金额默认隐藏；记录自身 `hideAmount` 同样生效，隐藏时金额和备注不得从详情或 VoiceOver 泄漏。转账分别展示两侧实际币种；余额调整标为调整后余额，不当成收入或普通差额。
- 服务器、账号或账本变化立即清空旧结果并拒绝迟到响应；冷启动核验身份与账本，失败显示重试而非空账本。回到前台重新核验，非活动状态显示隐私遮罩。
- 新增请求绑定服务器、账号和打开表单时的账本。结果未知时用原请求核对。编辑已有流水时，服务端通过详情版本检查并保留标签、图片和位置。编辑隐藏内容前需明确确认。

### Web 桌面工作台

- 当前桌面工作区最小宽度 1160px；宽屏外边距 92px，1370px 以下降为 40px。
- 顶部包含品牌、一级导航、搜索/通知/帮助和用户菜单。
- 左侧 56px 工具 rail，按钮 44×44；主内容弹性占满剩余空间。
- 页面结构通常为：标题与操作 → 指标卡 → 主列表/图表/编辑区。
- 数据列表允许高密度，但筛选、批量操作、加载和空态必须与表格明显分层。
- 小于桌面基线的设备使用已有 Framework7 Mobile 页面，不要强行把 1160px 工作台缩成手机布局。
- 账户设置在“安全设置”下方提供独立“AI 设置”（`?tab=aiSetting`），包含模型与用量、Agent 接入；移动 Web 使用设置 → AI 设置二级页，旧 Agent 链接保留兼容。共用浅色面板、中文正文字体、清晰文本色、18px 勾选框和至少 44px 操作目标，保持令牌名称/连接方式/有效期/权限/登录密码的顺序。
- Agent 令牌默认仅查询，写入权限分别勾选；完整令牌只在生成成功后显示，关闭或离开页面清除显示，列表不回显秘密。撤销采用可键盘操作的原生模态确认，并说明已有流水保留；禁用、加载、无令牌、生成失败及撤销失败均有可见文案。
- 令牌与 Codex 配置复制兼容 NAS 的 HTTP 页面；只在复制接口确实成功时显示成功。自动复制失败时全选可见内容并提示快捷键或长按复制，令牌另提供“全选令牌”按钮；临时复制节点立即清空并移除，不保存令牌。
- MCP 与 API 连接方式均可勾选账户与分类管理，切换连接方式保留选择。页面说明勾选只影响随后生成的新令牌，已有令牌不会自动升级；管理工具仍检查真实账本、成员权限、明确授权和删除引用。
- Agent 接入面板顶部显示“此账号的 MCP 接入”开关，带 switch / aria-checked，按钮只显示当前“已开启”或“已关闭”，不同时显示相反动作。状态从服务端读取，保存失败不能伪装成功；管理员全局关闭或限制账号时禁用开关。说明关闭会暂停全部 MCP 令牌，重新开启会恢复未过期且未撤销的令牌，API 与账目不受影响。
- AI 设置显示当前服务、模型、推理、超时、文本/图片开关和密钥是否已配置。DeepSeek 官方余额仅服务器所有者可查询，显示币种、可用/充值/赠送余额与查询时间；非官方兼容接口不猜测余额地址。用量只统计升级后当前账号通过 Finexy 的调用，支持今天/本月/累计及最近记录；缺少有效 usage 标为未计量，不估算 token 或费用，不重复相加缓存/推理子集。统计数据不包含提示词、返回正文、API 密钥或票据内容。
- Codex 配置示例引用环境变量，不嵌入令牌。Agent 账单导入必须经过解析预览、明确映射、重复核对和用户确认；解析和映射阶段不改变账户余额。Web 和 Android 导入当前选择的账本，预览标明目标账本；Web 更换账本后旧预览不得提交。Agent 接口须显式指定字符串账本 ID。

### Android

- 主导航固定为 5 项：总览、流水、记账、账户、设置。记账是中心主动作。
- Android 有新版安装包时在总览顶部显示轻量更新卡片，写明当前与新版本，提供“查看更新”和“忽略此版本”；只提醒 Android APK 的版本变化，不把服务端或桌面版发布当作 App 更新。
- 所有页面尊重 `safeDrawingPadding`、状态栏、导航栏和 IME；滚动内容底部至少为底栏预留空间。
- 手机主内容最大宽度 640dp；大屏居中，不让长文本无限延伸。
- 1.3× 以上字体由双列切换单列。横屏时优先保证可滚动、表单按钮可见，不压缩核心文字。
- 系统返回：子页面返回上一层；主 Tab 非首页先回总览；Dialog 先关闭 Dialog。

### 信息架构（Android 目标页面树）

底栏固定 5 项：总览、流水、记账、账户、设置，记账是中心主动作。**不允许新增底栏项或更换中心主动作**；新功能必须先在下表定位归属，再进入实现。Web 工作台维持既有导航结构，Android 信息架构不要求与 Web 逐项对应（见“平台一致性与差异”）。

| 一级 | 二级 / 子页面 | 状态 | 说明 |
| --- | --- | --- | --- |
| 总览 | 月度收支、预算卡、近期活动、待复核角标 | 基础版已交付 | 预算卡与待复核角标随对应阶段补齐 |
| 流水 | 流水列表、筛选（日期/类型/账户/分类/标签）、流水编辑、支付宝/微信支付账单导入 | 列表、编辑、五维筛选及账单导入入口已交付 | 筛选与统计、导出共用同一口径和设备时区自然日边界；导入先校对再确认入账 |
| 记账（中心） | 收入/支出表单、转账表单、应用模板、AI 文本记账、OCR 识别入口 | 收入/支出、模板应用及完整字段模板预览已交付 | 各流程见“功能流程规范” |
| 账户 | 账户列表、账户详情（余额/流水/日期筛选）、资产入口、汇率入口 | 列表、详情、默认选择、失效回退、资产管理及汇率管理已交付 | 资产页含折旧、估值、售出与删除；汇率页含来源、时间、新鲜度、换算及自定义汇率管理 |
| 设置 | 用户偏好、同步与冲突、分类映射、账户映射、标签管理、模板管理、预算设置、AI 与识别、通知、安全与隐私、数据与备份、服务器与账号 | 用户偏好已交付（账户/币种、主题/字号、启动/定期同步、金额/统计、AI 隐私与云同步）；标签增改、停用与确认删除已接入；当前账本月度预算在线设置已接入，验收见[专题](LEDGER_BUDGET_2026-10-04.md)；AI 与识别、通知为 phase-d-next 原型新增提案 | 保持二级页分组，禁止把全部设置重新堆回一个长页面 |

不在底栏的阶段 C/D 页面归属：

- 账本：全局切换器提供“创建账本”和“管理账本”；账本详情包含基本信息、成员、角色、邀请、退出与删除。单人账本与多人账本使用同一页面和权限模型。
- 创建账本：先选模板再填写名称；至少提供“个人账本”和“家庭共享”模板。模板只影响初始表单与建议，保存后不形成独立页面或永久类型分支。
- 标签管理、模板管理、预算设置、服务器与账号、数据与备份：设置二级页。
- 账户详情、资产、汇率：账户页进入的子页面。
- 统计与导出：从总览/账户页进入的独立子页面；导出是统计页内的动作，不单设页面。
- AI 待复核：总览角标 + 设置入口进入的队列页，不单设底栏项。
- Web 的“应用设置 → AI 配置”允许服务端所有者维护 OpenAI 兼容接口、模型、推理模式、超时和密钥。全局配置只允许最早创建且仍有效的账户修改；密钥不回显、不存浏览器，保存后服务端立即热切换并持久化。
- Web 更新提醒放在已登录的桌面总览/工作台和移动总览顶部。仅当官方正式 Release 版本高于当前服务版本时显示，服务版本不可用才以页面版本作比较；卡片明确标注比较来源，提供官方发布页和“忽略此版本”。关于页保留手动检查，失败须有可见反馈。提醒不自动升级自托管服务、不打断记账。

新增页面时必须同步更新本表；不允许出现表外页面。

### 账本中心流程（2026-09-16 重新设计）

本节为目标交互设计，替换独立家庭共享页面的设计。它不是已上线功能清单；现有页面与本节的差距见末尾“实现差距与验收”。颜色、字体、间距继续沿用第 4–6 节，不另建视觉系统。

#### 页面职责与入口

账本页的主任务是“找到一个账本，了解它，并管理它”。首页的主任务是“了解当前账本今天的状况并记账”。两页复用相同指标口径，但账本页不复制一整套首页。

- Web 工具入口统一命名“账本”，沿用 `/ledger/manage`。旧 `/family/manage` 重定向至账本列表；不能再出现创建家庭、解散家庭等前置操作。
- Android 保留五项底栏；设置 → 账本，以及顶栏切换器 → 管理账本，进入同一页面。
- 账本列表 → 账本详情；详情分为“概览 / 成员 / 设置”。Web 宽屏左侧列表、右侧详情；Android 和移动 Web 使用列表进入二级详情。
- 浏览详情只改变正在查看的账本；点击“切换到此账本”才改变全局记账上下文。详情始终显示账本名；当前账本标记“正在使用”，其他账本标记“正在查看”。
- 打开当前账本详情默认概览页；点击首页成员头像直接进入当前账本的成员页。

#### 账本列表与详情布局

视觉识别点是“账本名 + 细窄书脊标记 + 正在使用标签”，只在账本身份区域使用。珊瑚色表示当前选择；金额使用等宽数字，不给每个账本随机配色。主体采用白色表面、墨黑文字、低噪分隔线。

```text
顶部：Finexy   [当前：家庭日常 ▾]   总览 / 流水 / …

账本                                  用邀请码加入   [+ 创建账本]
管理自己的账本，也可以邀请他人共同记录
┌─────────────────┬────────────────────────────────────────┐
│ 搜索账本         │ 家庭日常                   正在使用     │
│ 全部 / 我创建的  │ 3 位成员 · 我的角色：所有者              │
│ / 我加入的       │ 概览        成员        设置            │
│                 ├────────────────────────────────────────┤
│ ▌家庭日常  当前  │ 本月收入    本月支出    本月结余         │
│   3 人 · 所有者  │ 账户余额（按币种）       数据更新时间   │
│                 │                                        │
│ 个人生活         │ 预算：已用 / 限额                      │
│   仅自己         │ 存钱目标：已存 / 目标                  │
│                 │ 最近流水                  查看全部     │
│ 装修记录         │ 类型 · 账户 · 记账人           金额    │
│   2 人 · 成员    │                                        │
└─────────────────┴────────────────────────────────────────┘
```

- 列表展示账本名、成员数、我的角色、是否当前账本。搜索按名称匹配；无结果显示“没有找到此账本”，附清除搜索操作。
- 默认排序为当前账本、最近使用、其余账本；我创建的/我加入的分类依据 owner 身份，不依据旧 family 类型。
- 列表不默认暴露其他账本金额，不在左侧堆收入、预算、目标等多组数字。右侧选中后才加载详情。
- 单人账本标记“仅自己”；有多位活跃成员则显示“3 位成员”。邀请未接受不计入成员数；任何标签都不是永久账本类型。
- 初次使用已有默认账本时展示它，并提供创建入口；用户不必创建第二个账本才能开始记账。

#### 如何创建账本

入口固定为账本页右上角与全局切换器底部的“创建账本”。采用两步对话框；Android 用可滚动的完整表单页，底部操作避开键盘。

1. 选择模板：“个人账本”（说明：自己记录日常收支）、“家庭共享”（说明：创建后邀请家人一起记账）。默认个人账本。模板仅预填名称和描述，图标使用已有账本/成员图标。
2. 填写名称（必填）和描述（选填），下方显示“创建后你是所有者，可随时邀请成员”。不要求先选人、建立家庭、创建账户或设置预算。底部按钮“上一步”“创建账本”。

成功后切换到新账本，进入详情概览，显示“账本已创建”。空账本引导以“添加第一个账户”为主动作，下方提供“邀请成员”“设置存钱目标”次级入口；设置账户时再选择币种和期初余额。创建家庭模板后邀请仍可跳过。

失败保持模板与全部输入，并在表单内解释原因；防止重复提交。前后端统一名称、描述长度规则，中文长度校验不能一端按字符、一端按字节。取消创建不改变全局账本。

#### 如何设置账本人员

成员页标题“成员”，右侧按权限显示“邀请成员”。依次展示活跃成员、待接受邀请；已退出/移除成员折叠到历史记录。成员行包含头像或姓名首字、昵称、“我”标记、角色、加入日期和“更多”菜单，危险操作不常驻每一行。

目标权限矩阵如下；服务端必须执行同样的规则，不能仅隐藏按钮：

| 能力 | 所有者 | 管理员 | 普通成员 | 只读成员 |
| --- | --- | --- | --- | --- |
| 查看本账本流水、余额、目标与成员 | 是 | 是 | 是 | 是 |
| 新增流水 | 是 | 是 | 是 | 否 |
| 修改/删除流水 | 按服务端流水编辑范围 | 按服务端流水编辑范围 | 按服务端流水编辑范围 | 否 |
| 管理账户、预算、目标、账本名称 | 是 | 是 | 否 | 否 |
| 邀请普通/只读成员、撤销邀请 | 是 | 是 | 否 | 否 |
| 调整普通/只读成员权限、移除他们 | 是 | 是 | 否 | 否 |
| 任免管理员、移除管理员 | 是 | 否 | 否 | 否 |
| 删除账本 | 是 | 否 | 否 | 否 |
| 退出账本 | 否 | 是 | 是 | 是 |

- 邀请弹窗包含“称呼（用于识别邀请）”“权限：普通成员 / 只读成员”，默认普通成员，有效期说明为 24 小时。生成后持久展示邀请码、到期时间、“复制邀请码”“撤销邀请”，不能只在短暂 toast 中显示。
- 邀请码为持有即可尝试加入的凭据，称呼不等于绑定账号；弹窗明确“仅分享给希望加入的人”，不宣称邀请码只对该称呼有效。
- 复制失败仍保留可选中的邀请码；复制成功显示“邀请码已复制”。生成失败保留输入；撤销成功后该条显示“已撤销”。过期必须单独标记，不统称“已处理”。
- “用邀请码加入”在没有自建账本时也始终可见。粘贴后先预览账本名称、邀请者、加入角色和可访问范围，再点击“加入账本”；预览需要新的只读邀请查询合同。加入成功后提供“切换到此账本”，不自动改变当前记账上下文。
- 调整角色使用带文字解释的单选表单，不能输入 2/3/4；所有者角色不可改。管理员不可操作其他管理员、不可提升自己。
- 移除前确认具体姓名与账本名，说明“对方将失去访问权限，历史流水保留”；成功后刷新成员与权限。退出同理；不删除退出者的历史流水。
- 单人账本也显示所有者和邀请入口。成员页加载失败与邀请列表无权限分别处理；普通成员看成员名单不应因邀请接口 403 而整页失败。

#### 如何展示账本数据

概览固定展示：月份选择、本月收入/支出/结余、账户余额、预算、存钱目标、最近五条流水。账本名称始终在数据上方可见。查看其他账本时，概览主动作是“切换到此账本”；切换前不提供快捷记账，避免写错账本。

- 本月收入/支出按自然月，结余 = 本月收入 − 本月支出；期初余额、余额调整、内部转账和存钱存取不进入收支。退款沿用统一的已实现收支口径，不能在新页自行另算。
- 账户余额是当前余额，不随月份变成历史月末余额，标签要明确；不同币种按币种展示小计，不能直接相加。有有效换算能力时才可显示带币种、报价时间的折合总额，汇率不完整显示“部分币种未折算”。
- 存钱目标资金与账户余额分别展示；不得把仍计入账户余额的目标资金再加一次形成虚高资产。
- 点击本月支出进入同账本、同月份、支出筛选的流水页；收入与结余的下钻保持对应口径。点击“查看全部”携带账本和日期，不丢掉详情上下文。
- 流水显示交易日期、类型、说明、账户、金额；共享账本可显示记账人。记账人不是付款人，未保存付款人时不能自动猜测；无成员消费排名。
- 每个模块独立表示加载和失败；接口失败显示“未能加载，重试”，不能用 0 代替。数字过期显示更新时间。真空列表才显示空态。
- 账本级权限与流水级权限共同决定可执行操作。旧 type=Family 不再决定只读；有权限但客户端写入尚未接通的入口应说明“当前版本暂不支持”，不能谎称成员权限不足。

#### 如何快速切换账本

Web 顶部固定显示“当前账本名 ▾”；Android 总览、流水、账户页顶栏使用同一切换器。不要要求先进入设置页，也不通过横滑首页隐式切换。

```text
当前账本：家庭日常 ▾
┌──────────────────────────────┐
│ 搜索账本                     │
│ ✓ 家庭日常   3 人 · 所有者    │
│   个人生活   仅自己           │
│   装修记录   2 人 · 成员      │
│ ──────────────────────────── │
│ 创建账本    用邀请码加入     │
│ 管理账本                     │
└──────────────────────────────┘
```

- Web 使用可键盘导航的菜单，Android 使用底部面板；选中有勾选和可读语义，不能只变颜色。账本多时支持搜索和滚动；操作入口始终可达。
- 从流水切换仍在流水页，从首页切换仍在首页；日期可保留，原账本的账户、分类、标签等不兼容筛选需清除并说明。
- 切换时各模块立即停止展示前一账本数据；优先呈现目标账本自己的缓存并显示同步时间，否则显示骨架。快速连续切换时旧请求不能覆盖新选择。
- 草稿固定绑定创建时的账本；切换前提供“保存草稿并切换 / 继续编辑”，不把旧草稿自动写入新账本。已提交的离线队列仍归原账本。
- 最近使用偏好以“服务器 + 用户 + 设备”隔离保存，重启恢复；不能让另一个用户继承。创建成功自动切换、接受邀请不自动切换是两个明确不同的成功行为。
- 权限撤销或账本被删除时立即阻止写入和继续展示缓存，提示失去访问，回到可访问的默认账本；本机未上传草稿单独保留待处理，不迁写。

#### 首页如何展示

首页只展示当前账本，顶部账本身份可点击切换；不默认汇总所有账本，以免多人共享和个人数据重复统计。

```text
[家庭日常 ▾]                       已同步 · 金额显隐
3 位成员 · 所有者                  [查看账本]

2026 年 9 月
本月收入          本月支出          本月结余

账户余额（按币种）                  查看账户
本月预算：已用 / 限额 / 剩余

存钱目标                           查看全部
旅行基金    已存 ¥6,000 / ¥10,000    60%

待确认入账 2 笔                     去处理
最近流水                           查看全部
……

Android 底栏：总览 / 流水 / 记账 / 账户 / 设置
```

- Web 保留现有主导航；收支摘要横排，下方流水主列与预算/目标辅列。Android 单列依次排列；金额可在最大字体下换行，核心数字不省略。
- 单人账本用“仅自己”替代头像堆叠，详情保留邀请入口；多人账本显示至多三个头像与总人数，点击进入成员页。
- 仅当当前账本有目标时展示存钱卡：一个目标显示完整进度，多个目标最多显示三个未完成目标和“查看全部”；仅有已完成目标时显示紧凑完成提示。目标百分比有数值文字，不仅有进度条；没有目标时不留大型空卡。
- 预算未设置时使用紧凑“设置本月预算”入口；只读成员不展示可操作的设置入口。
- 待确认数量必须归当前账本；现有用户级队列未支持账本筛选前，不得冒充当前账本待办，可单独明确标注“账号待办”。
- 有账户无流水：显示真实余额与“记录第一笔”；无账户：显示“添加第一个账户”。只读空账本提示“暂无记录，由可记账成员添加”。
- 金额隐藏状态作用于首页、账本概览与切换面板中的所有金额，不能通过进度旁金额或无障碍标签泄漏隐藏值。

#### 如何删除、退出与停用

本轮目标采用“仅所有者可删除空账本”，不设计一键清空历史数据；归档/恢复作为后续独立能力，未实现时不显示可点击的归档按钮。

1. 所有者进入详情 → 设置 → 底部“删除账本”。普通成员、只读成员和管理员在同一区域显示“退出账本”。所有者不能退出，当前方案不提供未经实现的所有权转移。
2. 删除前服务端返回影响预览：账本名、活跃成员、账户、流水、目标/资金记录、预算、周期模板/待确认等关联项及阻断原因。默认账本禁止删除。
3. 有关联财务数据时显示“暂时无法删除”，逐项展示阻断记录及相关管理入口；允许的账户迁移沿用既有完整性校验，不能自动删除关联数据来凑成空账本。客户端若有待同步队列/草稿另行提示，但不能代替服务端检查。
4. 无关联财务数据时展示“删除后所有成员将无法访问此账本，未使用邀请将失效”，要求输入账本名确认；按钮明确“删除账本”。取消/失败保留上下文。
5. 服务端在删除事务中再次核对所有者身份与关联数据，并防止并发新建记录；删除和新写入不能互相穿透。成功使全部邀请失效。重复确认返回可理解结果。
6. 删除当前账本后切换到默认账本并提示；删除正在查看的其他账本只返回列表，不改变当前记账账本。退出按同样规则回退，历史财务记录保留。

#### 实现差距与验收

当前代码已有直接账本成员/邀请合同、基础管理页、默认账本兼容和全局切换；本节不是宣称这些交互全部可用。已确认的差距：

- Web 已拆开详情浏览账本与全局当前账本；账本详情可在不切换首页/记账上下文的情况下读取账户数、流水数、存钱目标数、有效成员数及按币种汇总的可用账户余额。Android 账本管理页提供同一概览并允许返回默认账本。
- 邀请/角色操作仍有 window.prompt/confirm，邀请码依赖短暂提示；需换为有表单、错误、重试、焦点管理的应用内 Dialog。Android 成员移除需补二次确认、邀请撤销与完整角色选择。
- 成员/邀请加载需独立授权和状态，清理跨账本过期响应；普通成员不得被管理者专用邀请列表阻断。
- 删除权限、空账本事务校验以及 Web/Android 影响预览已接入；当前预览覆盖实际阻断删除的账户、流水、存钱目标、目标资金记录及月度预算，并展示有效成员与待接受邀请。服务端和桌面 Web 已增加实际周期模板及待确认/已忽略快照的数量与阻断原因；Android 的周期预览展示仍待接通，不能在客户端虚构关联数量。
- 当前管理员可调整非所有者角色；目标矩阵收紧为只有所有者可任免/移除管理员，必须补服务端校验与越权测试。
- 邀请预览合同与 Web/Android 两步确认已于 2026-09-17 接入；账本概览合同及两端展示已于 2026-09-20 完成隔离双用户验收。按角色写入全链路、首页账本级待办、偏好持久化与草稿绑定仍需逐项核对合同，不以“页面编译成功”代替功能验收。

实施顺序：权限与删除/邀请预览合同 → 统一切换状态及缓存隔离 → 创建/列表/详情/成员页 → 首页数据联动 → 两端专项与隔离 Docker E2E。

验收必须覆盖：两模板单人创建成功及失败草稿保留；无自建账本接受邀请；四种角色权限（含管理员不可提权）；移除/退出后访问失效且历史保留；有数据删除拒绝、空账本删除与并发写入互斥；默认账本保护；A→B→A 快速切换不串数据；只读与离线状态；首页目标随账本变化；Android 375 等效窄屏/横屏/大字体/深浅主题及 Web 375/768/1024/1440 自适应与键盘操作。

以下原有约束继续适用：

- 全局账本切换器末尾固定提供“创建账本”和“管理账本”，不得要求用户先进入家庭页面。
- 创建流程分两步：先选模板，再填写账本名称和描述。“个人账本”默认仅创建者一人；“家庭共享”提示创建后可邀请成员。模板不写入永久类型字段，用户以后添加或移除成员不会改变账本能力。
- 创建成功后立即切换到新账本，并进入账本详情或清晰提示下一步；失败时保留名称、描述和所选模板。
- 账本详情包含基本信息、成员列表、邀请管理、角色调整、退出账本和删除账本。所有者与管理员可以邀请和管理成员；普通成员可记账；只读成员只能查看。危险操作使用确认对话框。
- 单人账本也展示成员区，创建者是所有者，并可随时邀请其他人。成员全部退出后，账本仍是普通账本，不改类型、不迁移数据。
- 默认账本 id 0 继续作为兼容账本存在；在统一创建与管理流程成熟前不允许删除。其是否支持邀请由服务端迁移方案明确决定，界面不能自行模拟。
- 旧“家庭共享”页面迁移期间只提供跳转说明或兼容入口；新功能不得继续添加到该页面。兼容迁移验收完成后从导航移除。

## 8. 组件规范

### 按钮

- 主要按钮：每屏最多一个视觉最强项；Web 可墨黑/珊瑚，Android 使用主题 primary。
- 次要按钮：白色/raised surface、边框或 TextButton。
- 危险按钮：错误色文字或容器，并要求明确确认；不能用品牌橙代替危险红。
- Web 点击目标至少 44×44px；Android 至少 48×48dp。禁用态必须同时具备 disabled 语义和视觉弱化。
- 按压/hover 不改变布局尺寸；反馈在 80–150ms 出现。

### 卡片与列表

- 卡片用于聚合相关信息，不把每一行都做成不同风格的卡片。
- 标题、说明、金额、状态顺序稳定；金额右对齐或固定在明确区域。
- 列表行必须整行可扫读，删除等危险动作有可访问名称。
- 空态包含：发生了什么、下一步动作；不只放插画。

### 表单

- Web 登录页提供默认关闭的“记住账号和密码”；仅在登录及两步验证成功后保存，取消勾选立即清除。提示仅在个人设备使用，账号切换页不自动填入旧账号。移动端复选框必须保留原生键盘焦点与读屏语义。
- 桌面登录页的可见复选框为 18px，文字间距 8px，整行点击高度至少 44px；透明背景，不套用密码输入框的尺寸。保持原生键盘焦点与禁用状态。
- 始终使用可见 label，placeholder 只举例，不能代替 label。
- 错误靠近字段显示，说明原因和修复方式；提交失败保留用户输入。
- 异步提交显示 loading 并防止重复提交；不要让页面无反馈冻结。
- 金额在展示层格式化，业务层使用整数分；负号与交易类型语义不得相互矛盾。
- 键盘打开后主要提交按钮仍可滚动到达。

### Dialog、菜单和底部面板

- 打开后焦点进入标题或首个操作；关闭后尽量回到触发点。
- Web 的 Dialog 必须高于 drawer/popover；不要用无限增大的 z-index 掩盖 stacking context 问题。
- 冲突/覆盖/删除 Dialog 说明对象、影响范围和不可逆性。
- 长详情可滚动，确认按钮不被系统栏或键盘遮挡。

### 图标

- Web 使用当前 MDI 线性图标；Android 使用 `Mark` 中 1.7dp 圆角线条图标。
- 同一层级保持统一描边、大小和填充方式。结构性导航禁止 emoji 和随字体变化的字符图标。
- 图标按钮必须有 aria-label/contentDescription；纯装饰图标从无障碍树隐藏。

## 9. 数据可视化

- 管理页展示当前账本的全部末级账户，包括隐藏账户；账户详情按字符串 ID 关联，刷新后沿用 ID 并重新读取最新对象。有缓存时也必须显示真实详情；真正没有账户时才展示空态。总览标注全部账户数量，可见账户余额按币种汇总；每次展示一个钱包预览，通过左右切换浏览，并提供“查看全部账户”入口。

- 第一数据序列使用珊瑚，收入/正向使用绿；多分类再按蓝、靛、紫扩展。
- 图表必须有标题、时间范围、币种/单位、图例或直接标签；hover tooltip 不能是唯一读数方式。
- 不用颜色作为唯一分类手段，可辅以标签、线型、符号或顺序。
- 空数据不渲染虚假图形，显示空态和记账入口。
- 账户、日期、分类、标签筛选必须同时影响图、汇总和导出，不允许口径分裂。
- 动画只用于首次进入和数据更新，150–300ms；尊重 reduced motion。

## 10. 状态与反馈

所有数据页面都必须设计以下状态：

- 初始加载：skeleton 或小型进度指示，预留空间避免布局跳动。
- 空数据：解释 + 明确下一步。
- 成功：就地更新；必要时短暂 toast/snackbar，不打断流程。
- 失败：可见错误、原因、重试入口；Android 增加 live-region/error semantics。
- 离线：显示待同步/重试状态，不伪装成功。
- 冲突：同时展示本机与服务器字段，允许明确选择，不能自动静默覆盖。
- 权限/登录失效：保留本地未上传数据，说明重新登录后的行为。

### 全局同步状态指示器

同步状态必须有统一的组件定义，不允许各页面自行发明：

- 三种状态：**已同步**（低调展示或不展示，不用绿色大面积渲染）、**同步中**（小型进度指示）、**有待同步/失败**（警示橙角标 + 简短文字，如“3 条待同步”“上次同步失败”）。
- 展示位置：总览、流水页标题行内联角标；设置页保留完整状态、上次同步时间与手动同步入口。
- 状态不能只靠颜色区分，必须同时有文字或图标；失败状态必须提供原因摘要和重试入口。
- 点击角标进入同步详情：待同步条数、冲突条数、最近失败原因。
- 下拉刷新与手动同步共用同一状态展示，不出现两套进度指示。

## 11. 功能流程规范

本节定义阶段 C/D 关键功能的页面级交互。实现前先核对信息架构表中的归属；本节只定义流程与状态，视觉仍遵循前述章节。

### 11.1 转账与余额调整

- 入口：记账表单的类型切换增加“转账”；账户详情页提供“余额调整”。
- 转账表单字段：方向、金额、日期、备注和与方向相符的账户。账户间转账的转出/转入账户均必选且不可相同；外部转出只要求来源账户，外部转入只要求目标账户。手续费可选时必须明确说明计入哪一侧。
- 不同币种账户间转账只在缓存存在同一完整快照且报价仍有效时显示建议值，用户必须主动采用且仍可覆盖；汇率缺失或外部行情超过 96 小时时禁止自动折算，必须手动填写对侧金额。用户自定义汇率始终标记“用户维护、非实时市场价”，不得伪装为市场行情。
- 余额调整生成独立的“余额调整”类型记录；新账户的期初余额也使用该类型，**不得伪装成收入或支出**（对应已知 Web 问题）。
- 保存后两个账户余额即时更新；转账在两个账户的流水列表中以相反符号各出现一条，带转账图标与独立文案。
- 状态：离线保存为待同步；提交失败保留表单内容；冲突沿用现有冲突对话框机制。

### 11.2 OCR / AI 识别记账

流程为：文字/手动粘贴或拍摄/选择图片 → 裁剪/旋转 → 明确发送识别 → 建议预览 → 明确保存待复核 → 编辑复核与原子确认入账。识别失败时仍可保存来源后手动补全，不自动发模型或入账。

- 拍摄页只提供拍摄、相册选择等必要操作，不加滤镜和装饰动画。
- 识别中显示进度且可取消；识别失败必须给出原因、重试入口，并始终提供“改为手动记账”的降级路径。
- 图片可从相册选择或调用系统相机拍摄，发送识别前允许四角裁剪、90° 旋转和重置。Android 原图与草稿成功加密持久化后删除相机缓存文件，不写公共相册；保存失败明确提示并保留重读入口。原图、裁剪与旋转可从本机来源恢复。
- 裁剪区必须为 TalkBack 提供当前边界的可读描述，以及扩大、缩小、上下左右移动和恢复默认范围的替代操作；拖拽不能成为完成裁剪的唯一途径。
- 默认 OCR 流程先展示提取文字与总置信度；用户明确点击“发送并结构化”后才允许把文字发送到服务器配置的模型。若服务器所有者在 AI 配置中明确启用“模型支持图片（多模态）”，图片识别入口可将用户本次选择的原图直接发送给同一视觉模型；界面必须在发送前明确提示这一点，图片仅用于当次识别，不作为 AI 配置数据保存。结构化预览页展示：金额、日期、分类/商户等猜测字段。所有猜测字段必须带“AI 识别”标记，用户逐项确认或修改后才能入账；服务合同提供字段级置信度后，低置信度字段再用警示色高亮。
- 多张票据：以待确认列表逐条处理；只允许对用户已确认的条目批量入账。
- AI 文本记账：在记账页输入或粘贴文本 → 解析 → 进入同一结构化预览确认流程。
- 隐私文案：本地 OCR 必须明确说明“在本机处理”；如需调用大模型结构化，必须提供开关并在首次使用时二次确认。

### 11.3 AI 待复核队列

- 服务端 AI 生成但未经用户确认的条目进入“待复核”队列；入口为总览角标与设置页。
- 列表项显示来源（文本/票据/周期交易）、关键字段和置信度；单条操作：确认入账、编辑后确认、忽略。
- 确认入账先保存不可变请求，走同一账本的原子确认合同与生产 Worker；不使用“普通新增后 resolve”。忽略与恢复需要确认，已知回执只重新读取；未知结果重试原请求。
- 队列有新增时总览角标计数更新；队列为空时解释什么是待复核，并提供手动记账入口。

### 11.4 预算

- 预算设置（移动 Web / Android 设置二级页、桌面计划页）：当前账本的月度总预算 + 可选分类预算，金额业务层使用整数分。每月一份固定币种预算，所有者/管理员可管理，其他有效成员只读；默认个人账本 ID `0` 保持兼容语义。
- 只比较预算币种的净支出，退款冲减支出；收入、转账和余额调整不占用预算，其他币种不自动折算。分类额度独立提示，不相加替代总额度。必须完整读取当月流水、账户及分类后才能显示零或使用率。
- 修改和清除携带读取时的版本。冲突保留全部输入，先读取并展示服务器预算，再明确采用该版本作为基线，最后再次保存；刷新脏草稿不能自动提高版本或覆盖输入。删除后重新创建也不得复用旧版本。
- Web 未保存输入仅在当前面板的账本/月度范围保留，关闭或重载会丢失并有说明；Android 在线设置明确说明离线不可用。不把未保存预算写入流水队列或迁写至另一账本。
- 清除预算使用二次确认，说明总额度和分类额度一起清除、已有流水和账户余额保留。隐藏金额同时移除编辑输入、进度和可读百分比，不通过辅助标签泄漏。
- 总览预算卡：已用/总额、进度条、百分比和剩余金额文字。颜色语义：正常用品牌珊瑚或收入绿，达到 80% 用警示橙，超支用错误红；进度条不得是唯一表达。
- 超支提醒通过本地通知发出，频率可控（见“通知与提醒”）。
- 转账、余额调整和收入不计入预算；预算统计同币种支出与退款。

### 11.5 财务报告

- 以月报为核心：收支汇总、分类排行、环比变化；入口在总览。
- 图表遵循“数据可视化”章节；报告只读，不提供编辑，但每个数字可跳转到对应流水列表。

### 11.6 统计筛选与导出

- 筛选栏固定顺序：日期范围、类型（收入/支出/转账）、账户、分类、标签。
- 任一筛选变化必须同时作用于图表、汇总、列表和导出，禁止口径分裂。
- 导出是统计页内的动作：导出前展示将导出的条数与总金额并确认；文件与当前筛选、时区、金额格式、隐藏记录规则一致；导出失败保留筛选状态并可重试。

### 11.7 用户偏好

- 入口：设置 → 用户偏好。页面固定分为账户与币种、外观、启动与同步、显示与统计、AI 与隐私、云端偏好；窄屏与 1.3× 以上字体使用可滚动单列，不压缩标签和操作目标。
- 默认账户与默认币种是用户资料，保存后可跨设备同步；账户失效或隐藏时必须回退到首个可见账户并明确反馈，不保留不可选的幽灵值。
- 云端允许项仅包括非敏感显示/统计偏好。服务器成功拉取时覆盖其本地副本；拉取失败保留本地值并提供重试，保存失败保留当前表单和已写入的本地值，不伪装为已同步。
- 主题、字号、启动页和定期同步策略属于设备体验；AI 文本识别与云端结构化是当前设备、当前账本的隐私授权。PIN、token、生物识别状态及上述本地项永不上传。
- “手动同步”只关闭 WorkManager 周期任务；新增、编辑和删除产生的离线队列仍必须持久化并可由手动同步重试。
- 云偏好关闭时调用服务端关闭接口；重新开启前不得静默上传历史本地值。设置键必须经 typed allow-list、业务格式校验和非法值回退，禁止直接反序列化任意服务器键。

### 11.8 支付宝与微信支付账单导入

- 桌面流水页统一使用“导入账单”入口；在导入弹窗的文件类型中选择支付宝、微信或其他支持格式。预览、映射和写入仍绑定打开入口时的当前账本。

- 桌面导入及批量映射子弹窗复用 `finexy-dialog` 浅色表面、墨黑文字/主要按钮和珊瑚步骤指示。上传与完成步骤最大宽度 780px，核对表格及自定义列步骤最大宽度 1200px；内容可滚动，底部操作保持可到达。不要继承设备深色主题而与浅色工作台断层。
- 桌面 Web、移动 Web 与 Android 的入口均在流水页。支付宝支持 App 交易明细 CSV 与加密 ZIP，微信支付支持 XLSX 与 CSV。ZIP 密码仅在当前设备解压使用，不发送服务器。
- 解析结果先显示数量、类型、时间、金额与备注；未匹配的账户、末级分类必须由用户显式选择。可按原始名称成组映射，也可逐笔更改或取消勾选。
- 当前批量导入支持拥有写入权限的个人及共享账本，入口和预览明确显示打开时选定的账本；写入服务端按账本所有者分片并保存实际记账人。解析、映射、确认绑定同一账本，确认事务再次检查成员权限、账户映射和去重。仅提交已选且校验通过的记录；失败保留预览与映射。查重不能覆盖跨来源时间或描述差异，仍需人工核对。

- 与设置页手动同步共用全局同步状态指示器。

## 13. 动效

- hover/press/展开：150–240ms；页面与模态进入：200–300ms。
- 只动画 `opacity` 和 `transform`，避免高频动画 width/height、阴影模糊或背景滤镜。
- loading spinner 是允许的持续动画；普通装饰不做无限循环。
- Web 必须保留 `prefers-reduced-motion: reduce`；Android 使用平台动画缩放设置并保证无动画时信息完整。
- 动效表达空间关系或状态变化，不用于“让页面看起来更忙”。

## 14. 文案规则

- 使用简体中文、短句、主动语态；按钮用“动作 + 对象”，如“保存支出”“清空当前账本”。
- 不用技术错误码替代用户说明；可在次级详情中附错误码。
- 金融危险操作避免轻佻、游戏化文案。
- 同一概念固定称呼：流水、账户、分类、标签、模板、同步、服务器版本、本机版本。
- 金额默认 `¥ 1,234.56`，列表中收入带 `+`、支出带 `-`；余额调整和转账使用独立类型文案。

## 15. 平台一致性与差异

必须一致：品牌色、数据语义、术语、金额/时间口径、危险等级、空/错/加载/冲突状态。

允许不同：导航结构、信息密度、Dialog/Bottom Sheet 选择、hover 与触摸反馈、桌面表格与手机卡片。不要为了“跨端一致”牺牲平台惯例。

## 16. 禁止模式

- 不复活归档的紫色 + 荧光黄、像素狐狸或重游戏化方案。
- 不新增随意 hex、随机圆角、随机阴影或第二套图标体系。
- 不使用 emoji 作为导航/功能图标。
- 不依赖 hover 才能看到关键金额或操作。
- 不用 placeholder 代替 label，不在提交失败后清空表单。
- 不用纯静态假数据页面冒充功能完成。
- 不为解决层级问题直接写 `z-index: 99999`。
- 不只检查浅色或单一屏幕尺寸。
- 不让 AI/OCR 识别结果或周期交易在用户确认前自动入账。
- 不在信息架构表之外新增页面或底栏项。
- 不把期初余额或余额调整伪装成收入/支出。

## 17. AI 实施流程

1. 完整阅读本文和 `AGENTS.md`。
2. 读取目标平台基线源码，确认可复用组件/token。
3. 说明页面目标、用户主任务、状态和验收条件；先在信息架构表中定位页面归属，属于“功能流程规范”覆盖的功能必须按对应流程实现。
4. 先完善语义 token/公共组件，再实现页面；避免复制硬编码。
5. 覆盖加载、空、错误、成功、离线、权限和危险确认状态。
6. Web 验证 375/768/1024/1440px、键盘操作、100%/125% 缩放和 reduced motion；桌面工作台低于 1160px 时确认正确切换移动端体验。
7. Android 验证窄屏、横屏、最大字体、深浅主题、安全区、键盘和至少 48dp 触摸目标。
8. 检查正文 4.5:1、控件/图形 3:1、焦点顺序、可访问名称和颜色非唯一表达。
9. 用真实数据或隔离测试数据验证交互；截图只能作为视觉证据，不能替代断言。
10. 若设计基线改变，同步更新本文；不要另建 `V2`、`final2` 等并行规范。
