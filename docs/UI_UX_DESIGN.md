# Finexy UI / UX 设计基线

> 当前基线：2026-09-04。适用于 Web、PWA、Windows 桌面壳和原生 Android App。任何 AI 在新增或修改界面前必须先读本文，再读取对应平台的现有实现。若本文与代码不一致，以“当前基线源码”所列文件为准，并在同一次变更中更新本文。

## 1. 设计方向

Finexy 的体验关键词是：**清晰、克制、可信、温暖、可恢复**。

- 财务数据是主角，装饰不与金额、账户、风险提示争夺注意力。
- 品牌识别来自珊瑚橙、墨黑文字、暖/冷中性表面、圆润但不过度的容器。
- 主操作明确，次操作低噪；删除、覆盖、冲突解决必须让后果可理解。
- Web 与 App 保持同一品牌和语义，不要求逐像素复制。Web 偏高密度工作台，App 偏单手操作和渐进披露。
- 不延续旧版的紫色/荧光黄主色、像素狐狸游戏化、异形切角、重玻璃拟态或持续装饰动画。

### Android 四类流水录入

- 记账页使用同一分段控件切换支出、收入、转账和余额调整，切换后只显示当前类型必需字段。
- 转账必须明确显示转出账户与转入账户；两者不能相同。同币种只输入一次金额并说明自动记入，跨币种必须额外输入转入金额。
- 转账分类只允许已同步、可见的末级转账分类；缺少可用分类时显示可恢复提示，不用普通收支分类代替。
- 余额调整使用“增加余额/减少余额”分段，不要求用户输入负号；持久层将减少转换为负数。余额调整不显示分类和转入账户。
- 流水列表用“转账”“余额调整”文字与独立图标表达类型，不能只靠颜色。账户详情中的转账同时归属于转出和转入账户，并按所在账户一侧计算余额。

## 3. 品牌与视觉语言

### 标志

- 主标志是珊瑚橙底的白色 `F`，Web/Android 当前视觉尺寸约 34×34。
- 标志圆角约 11；不得拉伸、旋转或增加复杂光效。
- 产品名使用 `Finexy`，中文正文中不再使用旧称“栗子记账任务系统”。

### 视觉层级

1. 页面标题、核心余额、关键结果。
2. 当前任务的主要操作。
3. 筛选、状态、分类和账户上下文。
4. 帮助文字、时间、ID、同步详情。

单个可视区域只保留一个最强主操作。珊瑚橙用于品牌、重点和当前状态，不大面积铺满普通卡片。

## 4. 色彩系统

颜色必须通过语义 token 使用。已有源码中的硬编码色是待逐步收敛的设计债，不是新增硬编码的理由。

### 跨平台核心色

| 语义 | Web | Android Light | Android Dark | 用途 |
| --- | --- | --- | --- | --- |
| Brand coral | `#F05537` | `#F05537` | `#F05537` | 标志、强调、图表主序列、焦点提示 |
| Primary action | 墨黑 `#12141A` 或品牌珊瑚 | `#CB4027` | `#CB4027` | 主要按钮；白字时使用可达对比度的深珊瑚 |
| Income/success | `#149C63` / 强调态 `#087A49` | `#16845B` | `#62D3A0` | 收入、成功、健康状态 |
| Error/destructive | `#D94040` / `#B42318` | `#B3261E` | `#FF9D91` | 删除、失败、危险确认 |
| Warning/attention | `#DC6803`（正文用 `#B25309`） | `#B25309` | `#FDB022` | 预算接近上限、待复核、即将到期、汇率缺失 |
| Ink | `#12141A` / 强文本 `#101828` | `#1A1917` | `#F5F5F6` | 标题、金额、正文 |
| Muted | `#475467`–`#687181` | `#625D57` | `#ADB2BC` | 辅助说明；不得低于对比标准 |
| Canvas | `#F1F2F6` | `#F7F5F2` | `#101113` | 页面背景 |
| Surface | `#FFFFFF` | `#FFFFFF` | `#202226` | 卡片、主容器 |
| Raised surface | `#F7F8FA` | `#EEEAE5` | `#292C31` | 筛选、分段、次级区域 |
| Border | `#DFE3E9` / `#E9EBF0` | `#C8C0B8` | `#666B75` | 分隔线、输入边界 |

规则：

- 正文对背景至少 4.5:1，大文字和非文字控件至少 3:1。
- 收入/支出不能只靠绿/红表达，必须同时显示符号、类型文字或图标。
- 警示橙同样必须搭配图标或文字，不得作为预算接近上限、待复核等状态的唯一区分手段；警示色不得替代错误红用于危险操作。
- 图表类别可扩展蓝 `#2E9BFF`、靛蓝 `#4F46E5`、紫 `#7C3AED`，但珊瑚仍为第一序列。
- Web 当前工作台以浅色为生产基线；不要仅给局部组件添加“伪深色”。Android 必须同步维护完整深浅主题。
- 模态遮罩建议 40%–60% 黑；保证前景和背景层级明确。

## 5. 字体与数字

### Web

- 中文正文：`Microsoft YaHei UI`, `Microsoft YaHei`, `PingFang SC`, `Noto Sans CJK SC`, `system-ui`, `sans-serif`。
- 默认字号 14px、行高 1.5；普通正文不低于 14px，辅助文字原则上不低于 12px。
- 禁用合成字重：`font-synthesis: none`。Windows Chrome 需检查 100% 和 125% 缩放。
- 金额和数据可使用 `JetBrains Mono Variable` / `Cascadia Mono`，启用等宽数字；正文不要使用等宽字体。
- 旧版展示字体 `ZCOOL QingKe HuangYou` 不作为现行工作台默认标题字体。

### Android

| 层级 | 规格 |
| --- | --- |
| Display | 36sp / SemiBold / -1.2sp |
| Headline | 26sp / SemiBold / -0.5sp |
| Title large | 21sp / SemiBold |
| Title medium | 16sp / Medium |
| Body large | 16sp / 24sp |
| Body medium | 14sp / 21sp |
| Body small | 12sp / 18sp |
| Label | 14sp / SemiBold；小标签 11sp |

金额输入使用等宽数字，但无障碍读法必须保留完整币种与正负语义。最大系统字体下允许重新排版，不允许截断核心金额或操作。

## 6. 间距、圆角与阴影

使用 4/8 基础节奏：`4, 8, 12, 16, 20, 24, 32, 40, 48`。

| 场景 | Web | Android |
| --- | --- | --- |
| 页面外边距 | 92px（宽屏），1370px 以下 40px | 20dp；设置/认证页 24dp |
| 主容器 | 30px 圆角 | 页面不额外套总卡片 |
| 卡片 | 14–22px；大型卡片 24px | 18–24dp；钱包主卡 28dp |
| 输入框 | 11–14px | 16–18dp |
| 圆形/胶囊 | `999px` | `CircleShape` |
| 卡片内边距 | 14–24px | 14–24dp，标准 PanelCard 20dp |
| 区块间距 | 18–32px | 标准 20dp |

- 阴影用于悬浮菜单、Dialog、主 shell，不用于每一张普通卡片。
- Web 主 shell 当前为 `0 18px 55px rgba(18,20,26,.1)`；高层模态可更强，但不可同时叠加重边框、重阴影和玻璃模糊。
- Android 主要通过 surface 色差和 Material elevation 建层级；不要用模糊玻璃背景承载正文。

## 7. 布局与导航

### Web 桌面工作台

- 当前桌面工作区最小宽度 1160px；宽屏外边距 92px，1370px 以下降为 40px。
- 顶部包含品牌、一级导航、搜索/通知/帮助和用户菜单。
- 左侧 56px 工具 rail，按钮 44×44；主内容弹性占满剩余空间。
- 页面结构通常为：标题与操作 → 指标卡 → 主列表/图表/编辑区。
- 数据列表允许高密度，但筛选、批量操作、加载和空态必须与表格明显分层。
- 小于桌面基线的设备使用已有 Framework7 Mobile 页面，不要强行把 1160px 工作台缩成手机布局。

### Android

- 主导航固定为 5 项：总览、流水、记账、账户、设置。记账是中心主动作。
- 所有页面尊重 `safeDrawingPadding`、状态栏、导航栏和 IME；滚动内容底部至少为底栏预留空间。
- 手机主内容最大宽度 640dp；大屏居中，不让长文本无限延伸。
- 1.3× 以上字体由双列切换单列。横屏时优先保证可滚动、表单按钮可见，不压缩核心文字。
- 系统返回：子页面返回上一层；主 Tab 非首页先回总览；Dialog 先关闭 Dialog。

### 信息架构（Android 目标页面树）

底栏固定 5 项：总览、流水、记账、账户、设置，记账是中心主动作。**不允许新增底栏项或更换中心主动作**；新功能必须先在下表定位归属，再进入实现。Web 工作台维持既有导航结构，Android 信息架构不要求与 Web 逐项对应（见“平台一致性与差异”）。

| 一级 | 二级 / 子页面 | 状态 | 说明 |
| --- | --- | --- | --- |
| 总览 | 月度收支、预算卡、近期活动、待复核角标 | 基础版已交付 | 预算卡与待复核角标随对应阶段补齐 |
| 流水 | 流水列表、筛选（日期/类型/账户/分类/标签）、流水编辑 | 列表、编辑及五维筛选已交付 | 筛选与统计、导出共用同一口径和设备时区自然日边界 |
| 记账（中心） | 收入/支出表单、转账表单、应用模板、AI 文本记账、OCR 识别入口 | 收入/支出、模板应用及完整字段模板预览已交付 | 各流程见“功能流程规范” |
| 账户 | 账户列表、账户详情（余额/流水/日期筛选）、资产入口、汇率入口 | 列表、详情、默认选择与失效回退已交付 | 资产与汇率入口随阶段 D 补齐 |
| 设置 | 主题与外观、同步与冲突、分类映射、账户映射、标签管理、模板管理、预算设置、AI 与识别、通知、安全与隐私、数据与备份、服务器与账号 | 标签增改、停用与确认删除已接入；其余部分交付；AI 与识别、通知为 phase-d-next 原型新增提案 | 现有单页 `SettingsScreen` 必须按本表拆分为二级页 |

不在底栏的阶段 C/D 页面归属：

- 标签管理、模板管理、预算设置、服务器与账号、数据与备份：设置二级页。
- 账户详情、资产、汇率：账户页进入的子页面。
- 统计与导出：从总览/账户页进入的独立子页面；导出是统计页内的动作，不单设页面。
- AI 待复核：总览角标 + 设置入口进入的队列页，不单设底栏项。

新增页面时必须同步更新本表；不允许出现表外页面。

## 8. 组件规范

### 按钮

- 主要按钮：每屏最多一个视觉最强项；Web 可墨黑/珊瑚，Android 使用主题 primary。
- 次要按钮：白色/raised surface、边框或 TextButton。
- 危险按钮：错误色文字或容器，并要求明确确认；不能用品牌橙代替危险红。
- Web 点击目标至少 44×44px；Android 至少 48×48dp。禁用态必须同时具备 disabled 语义和视觉弱化。
- 按压/hover 不改变布局尺寸；反馈在 80–150ms 出现。

### 卡片与列表

- 卡片用于聚合相关信息，不把每一行都做成不同风格的卡片。
- 标题、说明、金额、状态顺序稳定；金额右对齐或固定在明确区域。
- 列表行必须整行可扫读，删除等危险动作有可访问名称。
- 空态包含：发生了什么、下一步动作；不只放插画。

### 表单

- 始终使用可见 label，placeholder 只举例，不能代替 label。
- 错误靠近字段显示，说明原因和修复方式；提交失败保留用户输入。
- 异步提交显示 loading 并防止重复提交；不要让页面无反馈冻结。
- 金额在展示层格式化，业务层使用整数分；负号与交易类型语义不得相互矛盾。
- 键盘打开后主要提交按钮仍可滚动到达。

### Dialog、菜单和底部面板

- 打开后焦点进入标题或首个操作；关闭后尽量回到触发点。
- Web 的 Dialog 必须高于 drawer/popover；不要用无限增大的 z-index 掩盖 stacking context 问题。
- 冲突/覆盖/删除 Dialog 说明对象、影响范围和不可逆性。
- 长详情可滚动，确认按钮不被系统栏或键盘遮挡。

### 图标

- Web 使用当前 MDI 线性图标；Android 使用 `Mark` 中 1.7dp 圆角线条图标。
- 同一层级保持统一描边、大小和填充方式。结构性导航禁止 emoji 和随字体变化的字符图标。
- 图标按钮必须有 aria-label/contentDescription；纯装饰图标从无障碍树隐藏。

## 9. 数据可视化

- 第一数据序列使用珊瑚，收入/正向使用绿；多分类再按蓝、靛、紫扩展。
- 图表必须有标题、时间范围、币种/单位、图例或直接标签；hover tooltip 不能是唯一读数方式。
- 不用颜色作为唯一分类手段，可辅以标签、线型、符号或顺序。
- 空数据不渲染虚假图形，显示空态和记账入口。
- 账户、日期、分类、标签筛选必须同时影响图、汇总和导出，不允许口径分裂。
- 动画只用于首次进入和数据更新，150–300ms；尊重 reduced motion。

## 10. 状态与反馈

所有数据页面都必须设计以下状态：

- 初始加载：skeleton 或小型进度指示，预留空间避免布局跳动。
- 空数据：解释 + 明确下一步。
- 成功：就地更新；必要时短暂 toast/snackbar，不打断流程。
- 失败：可见错误、原因、重试入口；Android 增加 live-region/error semantics。
- 离线：显示待同步/重试状态，不伪装成功。
- 冲突：同时展示本机与服务器字段，允许明确选择，不能自动静默覆盖。
- 权限/登录失效：保留本地未上传数据，说明重新登录后的行为。

### 全局同步状态指示器

同步状态必须有统一的组件定义，不允许各页面自行发明：

- 三种状态：**已同步**（低调展示或不展示，不用绿色大面积渲染）、**同步中**（小型进度指示）、**有待同步/失败**（警示橙角标 + 简短文字，如“3 条待同步”“上次同步失败”）。
- 展示位置：总览、流水页标题行内联角标；设置页保留完整状态、上次同步时间与手动同步入口。
- 状态不能只靠颜色区分，必须同时有文字或图标；失败状态必须提供原因摘要和重试入口。
- 点击角标进入同步详情：待同步条数、冲突条数、最近失败原因。
- 下拉刷新与手动同步共用同一状态展示，不出现两套进度指示。

## 11. 功能流程规范

本节定义阶段 C/D 关键功能的页面级交互。实现前先核对信息架构表中的归属；本节只定义流程与状态，视觉仍遵循前述章节。

### 11.1 转账与余额调整

- 入口：记账表单的类型切换增加“转账”；账户详情页提供“余额调整”。
- 转账表单字段：转出账户、转入账户（均必选且不可相同）、金额、手续费（可选，必须明确文案说明手续费计入哪一侧）、日期、备注。
- 不同币种账户间转账按当前汇率折算；汇率缺失时禁止自动折算，必须让用户手动填写对侧金额，并以警示色提示“汇率缺失”。
- 余额调整生成独立的“余额调整”类型记录；新账户的期初余额也使用该类型，**不得伪装成收入或支出**（对应已知 Web 问题）。
- 保存后两个账户余额即时更新；转账在两个账户的流水列表中以相反符号各出现一条，带转账图标与独立文案。
- 状态：离线保存为待同步；提交失败保留表单内容；冲突沿用现有冲突对话框机制。

### 11.2 OCR / AI 识别记账

流程固定为：拍摄或选择相册 → 裁剪/旋转 → 识别 → 结构化预览 → 确认入账。

- 拍摄页只提供拍摄、相册选择等必要操作，不加滤镜和装饰动画。
- 识别中显示进度且可取消；识别失败必须给出原因、重试入口，并始终提供“改为手动记账”的降级路径。
- 结构化预览页展示：金额、日期、分类/商户等猜测字段和原图缩略图。所有猜测字段必须带“AI 识别”标记，用户逐项确认或修改后才能入账；低置信度字段用警示色高亮。
- 多张票据：以待确认列表逐条处理；只允许对用户已确认的条目批量入账。
- AI 文本记账：在记账页输入或粘贴文本 → 解析 → 进入同一结构化预览确认流程。
- 隐私文案：本地 OCR 必须明确说明“在本机处理”；如需调用大模型结构化，必须提供开关并在首次使用时二次确认。

### 11.3 AI 待复核队列

- 服务端 AI 生成但未经用户确认的条目进入“待复核”队列；入口为总览角标与设置页。
- 列表项显示来源（文本/票据/周期交易）、关键字段和置信度；单条操作：确认入账、编辑后确认、忽略。
- 确认入账走正常同步链路；忽略需要确认对话框，并保留可恢复入口。
- 队列有新增时总览角标计数更新；队列为空时解释什么是待复核，并提供手动记账入口。

### 11.4 预算

- 预算设置（设置二级页）：月度总预算 + 可选分类预算；金额业务层使用整数分。
- 总览预算卡：已用/总额、进度条、百分比和剩余金额文字。颜色语义：正常用品牌珊瑚或收入绿，达到 80% 用警示橙，超支用错误红；进度条不得是唯一表达。
- 超支提醒通过本地通知发出，频率可控（见“通知与提醒”）。
- 转账、余额调整不计入预算；预算只统计收入/支出。

### 11.5 财务报告

- 以月报为核心：收支汇总、分类排行、环比变化；入口在总览。
- 图表遵循“数据可视化”章节；报告只读，不提供编辑，但每个数字可跳转到对应流水列表。

### 11.6 统计筛选与导出

- 筛选栏固定顺序：日期范围、类型（收入/支出/转账）、账户、分类、标签。
- 任一筛选变化必须同时作用于图表、汇总、列表和导出，禁止口径分裂。
- 导出是统计页内的动作：导出前展示将导出的条数与总金额并确认；文件与当前筛选、时区、金额格式、隐藏记录规则一致；导出失败保留筛选状态并可重试。

## 12. 平台能力扩展

### 通知与提醒

- Android 通知渠道至少划分：同步状态、预算提醒、周期交易提醒、AI 待复核；渠道可被用户单独关闭。
- 周期交易到期日生成待确认记录并通知，用户确认后入账；**禁止不经确认自动入账**。
- 提醒文案遵循文案规则，金融提醒避免制造焦虑；不发送任何推广类通知。

### 桌面小组件与快捷入口

- 最小集合：快捷记账入口（直达记账页并预选类型）与本月预算进度小组件。
- 小组件点击必须回到 App 内对应页面；小组件本身不提供数据修改能力。

### 触觉反馈

- 只在关键动作成功（保存、冲突解决）与失败/警示时使用轻量触觉反馈；普通列表点击不使用。
- 遵循系统触觉设置；关闭触觉时所有信息仍必须由视觉完整传达。

### 下拉刷新

- 总览、流水页支持下拉刷新触发同步；刷新中显示进度指示，失败显示内联错误与重试。
- 与设置页手动同步共用全局同步状态指示器。

## 13. 动效

- hover/press/展开：150–240ms；页面与模态进入：200–300ms。
- 只动画 `opacity` 和 `transform`，避免高频动画 width/height、阴影模糊或背景滤镜。
- loading spinner 是允许的持续动画；普通装饰不做无限循环。
- Web 必须保留 `prefers-reduced-motion: reduce`；Android 使用平台动画缩放设置并保证无动画时信息完整。
- 动效表达空间关系或状态变化，不用于“让页面看起来更忙”。

## 14. 文案规则

- 使用简体中文、短句、主动语态；按钮用“动作 + 对象”，如“保存支出”“清空当前账本”。
- 不用技术错误码替代用户说明；可在次级详情中附错误码。
- 金融危险操作避免轻佻、游戏化文案。
- 同一概念固定称呼：流水、账户、分类、标签、模板、同步、服务器版本、本机版本。
- 金额默认 `¥ 1,234.56`，列表中收入带 `+`、支出带 `-`；余额调整和转账使用独立类型文案。

## 15. 平台一致性与差异

必须一致：品牌色、数据语义、术语、金额/时间口径、危险等级、空/错/加载/冲突状态。

允许不同：导航结构、信息密度、Dialog/Bottom Sheet 选择、hover 与触摸反馈、桌面表格与手机卡片。不要为了“跨端一致”牺牲平台惯例。

## 16. 禁止模式

- 不复活归档的紫色 + 荧光黄、像素狐狸或重游戏化方案。
- 不新增随意 hex、随机圆角、随机阴影或第二套图标体系。
- 不使用 emoji 作为导航/功能图标。
- 不依赖 hover 才能看到关键金额或操作。
- 不用 placeholder 代替 label，不在提交失败后清空表单。
- 不用纯静态假数据页面冒充功能完成。
- 不为解决层级问题直接写 `z-index: 99999`。
- 不只检查浅色或单一屏幕尺寸。
- 不让 AI/OCR 识别结果或周期交易在用户确认前自动入账。
- 不在信息架构表之外新增页面或底栏项。
- 不把期初余额或余额调整伪装成收入/支出。

## 17. AI 实施流程

1. 完整阅读本文和 `AGENTS.md`。
2. 读取目标平台基线源码，确认可复用组件/token。
3. 说明页面目标、用户主任务、状态和验收条件；先在信息架构表中定位页面归属，属于“功能流程规范”覆盖的功能必须按对应流程实现。
4. 先完善语义 token/公共组件，再实现页面；避免复制硬编码。
5. 覆盖加载、空、错误、成功、离线、权限和危险确认状态。
6. Web 验证 375/768/1024/1440px、键盘操作、100%/125% 缩放和 reduced motion；桌面工作台低于 1160px 时确认正确切换移动端体验。
7. Android 验证窄屏、横屏、最大字体、深浅主题、安全区、键盘和至少 48dp 触摸目标。
8. 检查正文 4.5:1、控件/图形 3:1、焦点顺序、可访问名称和颜色非唯一表达。
9. 用真实数据或隔离测试数据验证交互；截图只能作为视觉证据，不能替代断言。
10. 若设计基线改变，同步更新本文；不要另建 `V2`、`final2` 等并行规范。
